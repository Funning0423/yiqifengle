# L6 湖畔棋盘镜头

只改了 kit 开启时的 `portraitFusion.main`（以及与它保持一致的顶层 `position` / `target` / `fovVerticalDeg`）。`short`、kit 关闭时的 b18 观光镜头、气球、场景和棋盘几何都没动。落子镜头仍走原来的 `lakesideAlignedLookAt` → `lakesideLandingBlend`，没有另加黑屏。

## 格子索引

`LakesideSceneData.lakesideCellCenter`：`index = row * 7 + col`，`x = -3.3 + 1.1·col`，`z = 8.7 + 1.1·row`，`y = 0`。第 0 行是远处（z 较小）的一行。

四角用的是同一格的 ±0.55 m（格子边长 1.1 m），高度用棋盘顶面 `topY = 0.02`。

## 镜头参数

竖屏 `h/w ≥ 2` 走 `main`。390×844 与 402×874、1206×2622 都在这条上。FOV 在比 390/844 更瘦的屏幕上按原来的 `lakesidePortraitFov` 略加宽，位置和朝向不变。

| | 旧 `portraitFusion.main` | 新 |
| --- | --- | --- |
| position | [0, 9.5, 23] | [0, 15, 24] |
| target | [0, 0.15, 10] | [0, 2.5, 4] |
| 垂直 FOV（390×844） | 50° | 66° |
| 垂直 FOV（402×874 与 1206×2622） | 50.203° | 66.242° |
| 俯角 | −35.72° | −32.01° |

`short`（更宽的竖屏，`h/w < 2`）仍是 [0, 10.2, 24] → [0, 0.1, 10]，FOV 50°。

安全区用的是没有微信窗口信息时 `boardSafeInsets` 的竖屏默认值：**上 47、下 34、左 0、右 0**（px，与传入的视口同一单位）。真机若上报 `wx` 安全区，数值会再取较大者；这次离线投影没有 wx。

## 两侧荷叶

95dc672d 上，盘两侧（|x| > 3.9，z 在 7.5–16.5）有左 35、右 20 片 `LK_lilypad`。旧镜头下中心全部出画。新镜头下 **55 片的中心都在画面内**。按网格半径（约 0.42×缩放）再量最外侧一点：左 27/35、右 17/20 的外沿也在画面内，其余 11 片只是外沿略出左右边，叶子主体在画面里。对比图上左右都能看到荷叶。

## 与 ff0d9c55 的棋盘差异

`scene/lakeside-board-fusion` @ ff0d9c55 没有并入。7×7 的水平位置没变：`LK_wb_line` 的 x/z 相同，只是 y 从 0.012 抬到 0.025。绳漂、两盏角灯笼、一只木筏有厘米级挪动。已有荷叶的 x/z 有小幅改动，并新增 18 片荷叶和 11 朵莲。格子公式 `LAKESIDE_GRID` 两边一样，所以这套镜头对两边的 49 格四角结论相同。

ff0d9c55 上 |x| > 4.8 的侧边荷叶/莲花中心，新镜头能放进 25/30。仍在画面外的 5 个都是融合分支新加的最外侧物件：`LK_lilypad_fz17`、`LK_lotus_fz19`、`LK_lotus_fz24`、`LK_lotus_fz25`、`LK_lotus_fz26`。再把它们整片拉进来会把近边格子压到现有测试的 44 px 下限以下，因此没有为它们继续拉远。

## 画面怎么来的

仓库里没有 Cocos 网页包，也没有 Blender。对比图是无头 Chrome（SwiftShader）里用 Three.js 光栅化的 **真实 GLB**：`scene_r5h_slim_transforms.json` 按 kit 开启的过滤放了 963 个实例（保留 `LK_piece_*`，丢掉资源模板和 `LK_board_frame`），调色板贴图是模型自带的 `T_LK_palette_256.png`。镜头是运行时同一条 `lakesideAlignedLookAt`（kit 开启）。角色是 `chr_b_r5g2_lod0_anim_pass2_INTERIM_s1_grokbot2.glb` 的 `idle_breathing_loop`（0.35 s），根节点放在 v4 停点 `[3.2531, 0.5714, 25.0904]`，朝向 −58°（路径末端航向）。她的包围盒 z 在 24.84–25.43，整个人在新镜头（z = 24，朝 −Z）和旧镜头（z = 23）的后面，所以两张图里都没有人。这和已接受的参考图一致。

这不是 Cocos 引擎帧。水面用的是 GLB 材质加一盏暖色方向光和半球光，没有游戏里的 `lakeside-water` 和日间校色，所以湖面比参考图更灰绿。几何、棋盘棋子和镜头是游戏内的。

信息牌在 y 96–156，工具栏中心在 390×844 的 y 730（点击高 64）。新盘面底边在 y 789，近端一两行会叠在工具栏上。安全区和屏幕边是按验收量的；参考图本身也把棋盘放在下半屏靠近底边。

## 测试

`tools/journey-integration/test-lakeside-camera.cjs`：13 项全部通过，包括 kit 关闭时 b18 镜头不变，以及 kit 开启时俯角 −28°…−48°、盘心在画面内、近边格子 ≥ 44 px、着陆间隙为 0。

`tools/journey-integration/run-suite.cjs`：371 项，308 通过，3 项只记录不拦（route-occlusion / route-framing / route-continuity），1 项因启动浏览器被跳过（navigation-guard），59 项失败。抽查失败原因是环境缺东西，不是这支镜头：`ggbot/full9c-final` 不在本地（meta-allowlist、meadow-encode-ext）、没有 `draco3d`（lake-leg-c、lakeside-touchdown-timeline、sky-lake-continuous 等）、没有 scipy、清单过期、气球飞行双写镜头。`lakeside-camera` 和 `lakeside-lens-guard` 是通过的。这次没有跑 Cocos 构建，也没有真机。
