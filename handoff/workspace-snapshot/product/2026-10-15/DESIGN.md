## 0. 一句话定位与设计原则

**定位**：一款安静、温柔的“边走边消除”的旅程小游戏——女孩推开小屋的门，一路追着风，穿过 8 个地区去找一个人；每通过一个地区，就拿到一件他留下的东西，最后在山丘上重逢。

**设计原则**

1. **场景是主角，棋盘是窗口**：棋盘长在场景里（§5），而不是盖在场景上。
2. **图形先说话**：图标大、文字小；任何提示先用场景物件和轻动效，再用一句短话。
3. **温柔不惩罚**：不设体力、不设断签惩罚、不用失败卡关逼广告。失败可以立即重试。
4. **每关一点新东西**：每个地区只引入 1 个新机制 + 1 件线索 + 1 段情绪；量少而精（参考 Monument Valley“只在有新东西可说时才加关卡”）。
5. **零花费**：Owner 不付费。全部用免费工具和免费资源；不依赖付费 CDN/服务器；广告只作可选、默认关闭的激励视频。
6. **包体先行**：30 MiB 总包上限下，任何新美术都先过包体预算（§3.3）。

## 1. 市场调研与功能差距

### 1.1 平台大盘（只引用有来源的数据）

- 2026 微信公开课 PRO 小游戏专场公布：2025 年小游戏整体 DAU 超 1 亿、MAU 5 亿；IAA（广告变现）休闲游戏用户月活超 4 亿；休闲用户兴趣主要集中在消除、解谜等经典玩法；“消除、益智类等女性向游戏在 2025 年取得了一波小小的爆发”，2026 年“以精美的画面、较独特社交趣味为主的女性向游戏的机会较大”；平台 80% 开发者为 30 人以下小团队。来源：[游戏葡萄 / 腾讯新闻，2026-01-15](https://news.qq.com/rain/a/20260115A088A600)
- 同一来源：2026 年 IAA 政策提供“30 天内最高 90% 分成”或“90 天内最高 85%”两种选择。（只说明平台倾向扶持 IAA，本项目不以收入为目标。）
- 包体限制：微信官方文档写明“整个小游戏所有主包+分包大小不超过 30M、主包不超过 4M、单个普通分包不限制大小、单个独立分包不超过 4M”。来源：[分包加载 | 微信开放文档](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage.html)。注意：另一页旧文档写“代码包总大小不能超过 20M（开通虚拟支付后的小游戏不超过 30M）”（[代码包 | 微信开放文档](https://developers.weixin.qq.com/minigame/dev/guide/framework/code-package.html)），两页说法不一致，**上线前需在 MP 后台用真实上传核一次**。本文按 30 MiB 规划，并把目标压到 ≤ 24 MiB 留余量。

> 结论：本作的方向（精美画面 + 消除/解谜 + 温柔情感）与平台公开的休闲品类趋势一致；但本项目首先是送给一个人的礼物，目标是“好玩、好看、能玩到结局”，而不是买量和变现。

### 1.4 QIFENGLE 现状与差距

依据 10-15 接手盘点（`takeover-2026-10-15/PLAN.md`）：

- 已有：开场（坐 → 起身 → 走到门 → 开门 → 升镜看岛和灯塔）、12 主关 + 9 海岸关、3 个地区（海岛/草甸/天空之城）和 3 种地区道具（潮汐网/日光种/星丝剪）、通关宝箱 `ResultChest3D`、地区挑战奖励、3 首 BGM + 环境声 + 约 26 个音效、微信构建可启动。
- 缺口：
  1. 包体约 28.1 MiB，离 30 MiB 只差约 1.9 MiB；草甸 GLB 6.3 MB、室内 5.2 MB、角色 3.4 MB 最大——**不瘦身就加不了任何新地区**。
  2. 棋盘背景是一张 750×1624 静态图（10-10 视觉拒收仍未解决）。
  3. 没有区域过场镜头（只有加载）、没有专门的回家运镜（现在是直接切）、没有世界地图拖动视图。
  4. 加载页背景是电影剧照占位图——**正式包不能出现**。
  5. 盘点里未见故事/线索系统、收集/彩蛋图鉴、每日内容、分享卡（未逐行搜代码确认，GGbot 接手时先核一次）。
  6. 道具与按钮缺少 3D 体积（拒收项）；宝箱未按原版 `treasure.js` 验收。
  7. BGM 授权来源未登记。

## 2. 故事：《风会带我去找你》

### 2.1 原创边界（必须遵守）

- 只借用电影《起风了》的**氛围**：风、飞翔、远方的思念、日常里的克制。**不使用**其中任何角色、名字、台词、情节或标志性画面。
- 明确避开：飞机设计师/战争题材、疾病与离世、在风中接住被吹走的帽子或阳伞的相遇桥段、山坡写生 + 阳伞的构图、电影剧照与海报元素。
- 天空之城里的巨型机器人要做成**原创造型**（圆润、风车/风帆元素、铜绿色风标头），避免与其他知名动画中长满苔藓的守护机器人轮廓相近；由 grokbot-2 做轮廓对比检查。
- 名字全部原创：女主 **阿芳**；男主 **阿宁**；天空之城的守风机器人 **老铆**。

### 2.2 一句话故事

三年前，做风筝的少年阿宁离开小岛，说“等我做出能载两个人的风筝，就飞回来接你”。后来信断了。一个起风的早晨，一只纸飞机落在阿芳的门口——她推开门，决定这一次换她去找他。

### 2.4 分章大纲

**序章 · 门外的纸飞机（R1 海岛灯塔）**
- 开场沿用现有演出：阿芳坐在小屋里 → 窗帘被风掀起 → 她起身、走到门口、推门 → 镜头升起，露出海岛与灯塔。
- 门口台阶上落着一只纸飞机。打开是半句话：“等风来，我就——”（后半句被雨水洇掉）。
- 第 1 关通关后：海鸥把纸飞机吹向码头，她跟过去，发现码头的小船帆上画着同样的风筝记号 → 乘船去草甸（§4.2）。
- 海岸 9 关为可选支线：沿着海滩捡贝壳，每过一关向灯塔方向走几步，最后在灯塔顶点亮“夜航灯”（沿用现有夜航完成条件）。

**第一章 · 风车下的信（R2 风车草甸）**
- 草甸的风车停着。阿芳消除杂草、让风车重新转起来。
- 通关：风车转动，磨坊的抽屉被震开，掉出阿宁的第一封信——原来他在这里学会了“看风”。
- 情绪点：信的末尾写“替我看看海”，她回头看见远处的灯塔，第一次笑出声。

**第二章 · 守风的老铆（R3 天空之城）**
- 云上的城安静得像睡着了。巨大的守风机器人老铆一动不动，手指上系着一条黄色围巾——那是阿芳三年前亲手送给阿宁的。
- 通关：城里的风车阵重新转动，老铆醒来，把围巾递还给她，然后用手指指向远方：风往东走。
- 情绪点：她把围巾系回脖子上。从这一章起，阿芳的模型戴上黄色围巾（围巾成为后续每章的风向指示，飘的方向=下一站）。

**第三章 · 会唱歌的湖（R4 风铃湖畔村）**
- 湖边每户人家都挂风铃。村里的小孩说：“以前有个哥哥，帮我们每家做了一只。”
- 通关：最后一只风铃挂回桥头，一阵风吹过，所有风铃一起响。最旧的那只上刻着两个小小的名字：岚、栀。
- 情绪点：第二封信——“我在每一个有风的地方，都练习叫你的名字。”

**第四章 · 单程票（R5 秋林铁路）**
- 落叶铺满铁轨，小火车停在林中小站。
- 通关：站长的抽屉里有一张三年前的车票，上面印着“单程”。
- 情绪点（不安）：她握着车票坐在空站台上，风停了，画面短暂褪色 2 秒；然后一片红叶落在她手心，风又起了。她上了车。

**第五章 · 观风的人（R6 雪夜观星台）**
- 雪山上的观星台，望远镜对着天空，桌上一本厚厚的日志。
- 通关：日志每一夜都记着风速和风向。最后一页写着“秋分后第七天，会有一年里最大的风”，页角画着一个戴帽子、系围巾的女孩。
- 情绪点（理解）：他没有不回来，他在等一阵足够大的风。

**第六章 · 断翼（R7 云海）**
- 云海上漂着一片破掉的风筝翼——是一只两人座风筝的试飞残骸。
- 情绪最低谷：阿芳以为他出事了，蹲在云边。老铆从云里升起来，把她托在掌心（R3 的回收）。
- 通关：风筝翼的夹层里有最后一封信：“如果这只风筝飞不到你那里，我就走着去接你。”——试飞失败了，但他人没事，他决定走回去。
- 情绪点（勇气）：她站起来，围巾指向一座山丘。

**终章 · 起风了（R8 山丘重逢）**
- 夕阳下的山丘，一只崭新的大风筝停在坡顶。阿宁背对着她，正在系最后一根线——他本来打算第二天出发去接她。
- 通关（最后一关难度刻意降低，见 §3.4）：风来了。
- 重逢对白（字幕，无配音）：
  - 阿宁：“我本来……明天就要去接你的。”
  - 阿芳：“我先来了。”
  - 阿芳把门口捡到的纸飞机递给他。他摇摇头，从口袋里拿出同一页纸的另一半——后半句是：“等风来，我就去接你回家。”原来序章那只纸飞机，是他在最大风那天从山顶放出的“试飞”，风把它一路送到了她的门口。
  - 两人同时抬头：“咦，起风了。”
- 结局演出：两人乘大风筝起飞，飞过云海、雪山、秋林、湖畔、天空之城、草甸，回到海岛（§4.10 结局回家）。每飞过一个地区，那里就亮起本区主色（参考 Gris 把颜色还给世界）。
- 尾声：小屋里原本只有一把椅子，现在多了一把。灯塔亮起。镜头从门外缓缓退出——和开场的推门呼应。
- 通关后：解锁“风之手帐”完整版（8 件线索 + 信件全文 + 风物志）。

- **氛围**：夕阳，暖风。**色板**：夕阳橙 #F29E4C、草金 #D8C27A、天空粉紫 #C9A3C9；结局时其他地区颜色依次回归。
- **地标**：坡顶的两人座大风筝。
- **资产**（≤ 0.6 MiB）：山丘（复用草甸地形变形 + 换色）、大风筝（≤ 1.5k 面，布面 4 骨）、阿宁（**复用阿芳的骨架与动画**，只换头发/衣服模型，≤ 3k 面），萤火虫粒子。
- **新机制：放风筝线**——棋盘一侧是风筝线，沿线消除让风筝升高；**不加新障碍**，前两关回顾全部机制。
- **难度**：新36 中 → 新37 中 → **新38 易**（结局关：保证大多数玩家 1–2 次通过，奖励是故事不是挑战；参考 Monument Valley“挑战不是重点，结局很重要”）。
- **线索**：另一半纸 + 重逢。

### 3.3 包体预算（30 MiB 上限）

| 项 | 当前（盘点） | 目标 |
|---|---|---|
| 主包（引擎 + 开场小屋 + 海岛最小集） | 约 1.9 MB（未正式核） | ≤ 3.5 MB |
| 室内 GLB | 5.2 MB | ≤ 2.0 MB（Draco + 贴图压缩） |
| 角色 | 3.4 MB | ≤ 2.0 MB |
| 草甸 GLB | 6.3 MB | ≤ 2.5 MB |

| **现有内容合计** | 约 28.1 MiB | **≤ 20 MiB** |

省包体的硬规则：
1. **一个地区一个分包**（Cocos Asset Bundle → 微信分包），进入该区前预下载下一区。
2. **顶点色优先**：新地区不使用独立贴图，全部共享一张 256² 调色板贴图（low-poly 风格天然适合）。
3. **模块复用**：岩石、树、云、草全部 instanced；阿宁复用阿芳骨架；火车复用到转场；R8 山丘复用草甸地形。
4. **音乐变奏**：新区 BGM 用同一主旋律的变奏短循环（60–90 秒，单声道），参考 A Short Hike 同一主题在各地区变奏的思路。
5. **不依赖付费 CDN**：所有资源进包；若未来需要远程资源，先确认有免费且合规的方案再说（未核实，暂不采用）。

### 3.4 难度曲线

- **地区内锯齿**：教学（易）→ 上升 → 高峰（倒数第 2 关的前一关）→ 回落 → 剧情关（中）。剧情关永远不是最难的一关，避免“故事被难度卡住”。
- **全局**：两处高峰（主11、新28），终章回落。
- **调参依据**：以“首次通过率”和“放弃率”为准。Playrix 的经验是遇到高放弃率关卡时宁可换成新关，也要降低放弃率（[Game World Observer](https://gameworldobserver.com/2019/09/27/playrix-levels-elements-match-3)）——本作不变现，更应如此。
- **温柔保底**：同一关连续失败 3 次，开局送 1 个星光；连续失败 5 次，提供“+5 步”（免费，不看广告）。
- **棋子种类**：Royal Match 前期大量关卡只用 4 种基础棋子，让玩家更容易找到消除（[Gamigion](https://www.gamigion.com/what-makes-royal-match-so-good-level-design/)）。建议教学关和剧情关用 5 种逻辑棋子，其余 6 种。

## 4. 场景转场与运镜

### 4.1 通用规则

- 所有转场都在**同一个稳定世界**里发生（GDD：岛、海、云关系不变，不复制云、不拉伸地形）。
- 时长：常规转场 8–14 秒；**第一次观看后，第二次起可点击跳过**（右上角小“跳过”，图标为主）。
- 根位移只由一个驱动负责（动画或脚本二选一），避免滑步；行走速度与离屋行走一致；镜头巡航沿用出门运镜约 7 m/s 的上限。
- 镜头不穿模、不长时间被遮挡、不贴脸裁切；转场期间禁止输入棋盘，结束时清理所有残留输入、粒子与弹层。
- 音乐：转场开始 0.5 秒内当前地区 BGM 淡出，抵达时下一地区 BGM 在 1.5 秒内淡入（交叉淡入）；风声作为两段之间的“桥”。
- 下一地区分包在玩家进入**前一地区最后一关**时开始后台预下载；转场结束前未下载完，则让镜头在“抵达定格”镜头多停留并显示三朵小云加载（不显示百分比，遵守 GDD 加载页规范）。

### 4.2 海岛 → 草甸：选择“小帆船”

| 方案 | 优点 | 缺点 |
|---|---|---|
| **小帆船（采用）** | 海岛与草甸隔着海，坐船符合世界逻辑；帆被风鼓起正是“咦，起风了”的画面；复用现有海面 shader 和岸浪；船 ≤ 1.5k 面，成本低；镜头可以回望海岛和灯塔，呼应开场 | 需要做上船/下船两段短动作 |

## 5. 活的棋盘（Living board）

> Funning 的要求：每个地区的棋盘都“长在场景里”——边框和格子跟场景一个材质、棋子有体积、背景是真实 3D 场景在动、棋盘边上有会回应玩家的小动物和隐藏彩蛋，并有一本记录发现彩蛋的图鉴。

### 5.1 总体结构（所有地区通用）

```
屏幕（750 设计宽，竖屏）
├─ 层 0  动态背景：真实 3D 地区场景，固定“棋盘机位”实时渲染（海/云/草/风/昼夜）
├─ 层 1  小动物与彩蛋：只出现在棋盘边框外的“栖息点”（每区 4–6 个）
├─ 层 2  棋盘边框 + 格子（地区主题材质，3D 低模或烘焙精灵）
├─ 层 3  棋子（6 种逻辑类型 × 地区外观，带体积）
├─ 层 4  特效（消除、连消、特殊棋子）
└─ 层 5  HUD（目标/步数在上，道具托盘在下；全部在安全区内）
```

**通用规则**

1. **边界清楚**：棋盘外框完整落在安全区内（`wx.getSystemInfoSync().safeArea`），左右各留 ≥ 24 px（750 设计宽），上方给 HUD 留出，下方给道具托盘留出；外框与背景之间有一圈 6–10 px 的暗色描边或投影，保证在任何昼夜状态下都能一眼看出棋盘边界。
2. **棋子先读形状再读颜色**：6 种逻辑棋子在每个地区都保持“形状差异 + 颜色差异”双编码（色弱也能玩）；尺寸占格子 82–88%；顶面亮、侧面暗、底部接触阴影——有体积。参考 Royal Match 用更大、更高对比、形状各异的棋子提升可读性（[Deconstructor of Fun](https://www.deconstructoroffun.com/blog/2021/3/21/royal-match-the-new-king-from-turkey)）。
3. **图标大，文字小**：目标栏用棋子图标（≥ 64 px）+ 小号数字；道具托盘只有图标和角标数字，不写说明文字；说明只在长按时出现一行。
4. **背景不能抢棋盘**：背景在棋盘区域后方自动降低饱和度 15–25% 并加轻微景深模糊（或用暗化渐变面片代替真模糊，省性能）；动态元素在棋盘正后方速度减半。
5. **装饰不影响规则**：小动物、彩蛋、背景动效使用**独立的装饰随机数**，不消耗玩法随机数，不改变同一局的复现（GDD W06）。
6. **输入优先级**：棋盘区域内的触摸永远属于棋盘；小动物只能在棋盘外框以外的栖息点被点到，热区 ≥ 88×88 px（750 设计宽）；拖拽棋子时小动物不响应。
7. **昼夜**：与地图共享同一个昼夜参数（0–1）；背景、边框材质、棋子高光一起变化，夜间棋子加一圈轻微自发光描边保证可读（解决 r14“夜牌对比度不够”）。

### 5.2 棋子与边框的立体做法

- 推荐做法（与 PLAN 一致）：在 Blender 里做低模 + 烘焙光影，渲染成带厚度、侧面、高光的精灵图（常态/选中/消除前闪三帧），进同一张地区图集——**1 个 draw call 画完全部棋子**，同时有 3D 观感。
- 可选做法：棋子用真实 3D 低模（每个 ≤ 200 面）+ GPU Instancing。仅在高端机档位开启，低端机回退到精灵图。
- 边框：真实 3D 低模（≤ 3k 面），烘焙 AO 到顶点色，无实时阴影；格子底板为一张共享材质的 instanced 面片，奇偶格明暗交替。

### 5.3 各地区棋盘设计

#### R1 海岛灯塔
- **(a) 边框/格子**：浮木拼成的木框，四角是缠绳的系缆桩；格子是湿润的浅沙色石板，奇偶格深浅交替；左下角嵌一枚小贝壳（不遮格子）。

### 5.4 小动物反应规范

| 项 | 规则 |
|---|---|
| 同屏上限 | 同时**正在播放动画**的小动物：高档机 ≤ 3，中档 ≤ 2，低档 ≤ 1；其余保持静止姿态或隐藏 |
| 点击冷却 | 同一只 1.5 秒；连续点击进入“隐藏计数”（用于彩蛋触发） |
| 连消阈值 | 连消 ≥ 3 触发“小庆祝”，≥ 5 触发“大庆祝”；同一回合最多 1 只小动物响应，避免抢戏 |
| 通关 | 结算宝箱出现前 0.8 秒，所有小动物做一次通关反应，然后让位给居中宝箱 |
| 失败 | 小动物做一个安慰动作（低头/靠近），不做嘲讽 |
| 遮挡 | 任何时刻不进入棋盘外框以内；不遮挡 HUD 数字和道具图标 |
| 声音 | 每只小动物 1–2 个短音效（≤ 0.6 秒，CC0 来源），受“音效”开关控制；同一时刻最多 2 个小动物音效 |

### 5.5 动态背景实现与降级

| 档位 | 背景做法 | 说明 |
|---|---|---|
| 高 | 真实 3D 场景 + 固定棋盘机位实时渲染；海面/草/树为顶点 shader 动画；云 instanced；昼夜为全局参数插值 | 无实时阴影、无后处理；烘焙 AO 进顶点色 |
| 中 | 同上，但远景合并为一个静态网格；云数量减半；关闭远景小动物 | |
| 低 | 3 层视差（天、远景、近景各一张烘焙图）+ shader 波光/草摆；昼夜仍用颜色插值 | PLAN 中已列的退路 |

档位由首帧性能测量自动决定（前 3 秒平均帧时间），玩家也可在设置里手动切换“流畅/精美”。

### 5.6 风物志（彩蛋图鉴）

- 入口：风之手帐的第二个标签页（图标：一片羽毛）。
- 结构：8 页，每页一个地区；每页 3 个“常见小动物”+ 2–3 个“稀有彩蛋”。未发现时显示**剪影 + 一行小提示**（如“夜里，沙滩上会有慢慢走的客人”），发现后显示截图式插画、发现日期和第一次发现的那关。参考 Neko Atsume 的 Catbook（记录来访的猫与照片，未知项以剪影显示）（[Neko Atsume Wiki](https://nekoatsume.fandom.com/wiki/Catbook)）和 Alba 不评分、轻松的动物图鉴（[NME](https://www.nme.com/reviews/head-alba-a-wildlife-adventure-review-sun-sea-and-socially-conscious-photography-2964692)）。
- 首次发现：画面边缘弹出小图标 + 一声轻铃，不打断操作；本关结算时再展示一次。
- 奖励：**只给装饰**——每页集齐解锁该地区的一款边框装饰或宝箱皮肤；不给任何影响难度的道具。
- 保底：概率彩蛋采用“伪随机 + 保底”，每多一次符合条件但未出现，概率递增；最迟在第 N 次（N = 1/概率 × 1.5，向上取整）必出，避免玩家永远见不到。
- 存档：独立键 `qfl-fengwuzhi-v1`，只记录“已发现 ID + 日期 + 关卡”，不进入主线存档事务。

### 5.7 性能预算（微信小游戏，棋盘场景）

参考值：Cocos 社区对移动端的常用建议是 Draw Call ≤ 100、三角面 ≤ 10 万/帧、渲染耗时 ≤ 10 ms（[Cocos 中文社区](https://forum.cocos.org/t/topic/166206)）；同为 Cocos Creator 3 的微信小游戏《最强魔斗士》把 Draw Call 控制在 40 以下，并用 GPU Instancing 和静态合批降低开销（[Cocos 官方 · 微信公开课分享](https://www.cocos.com/post/9ed27554c893b5bad850a422c3538c15)）；2D 合批需同材质、同图集、节点连续，Mask 会打断合批（[Cocos Creator 3.8 合批文档](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/engine/ui-batch.html)；[腾讯云开发者社区](https://cloud.tencent.com/developer/article/2202652)）。本作取更保守的预算：

| 项 | 高档 | 中档 | 低档 |
|---|---|---|---|
| 目标帧率 | 60 fps | 30 fps 稳定 | 30 fps |
| **Draw Call 总计** | **≤ 70** | ≤ 55 | ≤ 40 |
| └ 动态背景（3D 场景） | ≤ 30 | ≤ 20 | ≤ 6（3 层视差） |
| └ 边框 + 格子 | ≤ 4 | ≤ 4 | ≤ 3 |
| └ 棋子（同一图集一批） | ≤ 3 | ≤ 3 | ≤ 3 |
| └ 小动物 + 彩蛋 | ≤ 8 | ≤ 5 | ≤ 3 |
| └ 特效 | ≤ 10 | ≤ 8 | ≤ 6 |
| └ HUD / 托盘 / 文字 | ≤ 15 | ≤ 15 | ≤ 15 |
| **三角面总计** | **≤ 70k** | ≤ 45k | ≤ 20k |
| └ 背景 | ≤ 45k | ≤ 28k | ≤ 4k |
| └ 边框 + 格子 | ≤ 4k | ≤ 4k | ≤ 3k |
| └ 棋子（3D 模式 49 × ≤ 200） | ≤ 10k | 精灵（≈ 100） | 精灵 |
| └ 每只小动物 | ≤ 1.5k（蒙皮 ≤ 16 骨） | ≤ 1k | ≤ 800 |
| **同时动画的小动物** | **≤ 3**（其中蒙皮动画 ≤ 1，其余为节点/顶点动画） | ≤ 2 | ≤ 1 |
| 粒子总数 | ≤ 120 | ≤ 60 | ≤ 30 |
| 棋盘场景贴图显存（新增） | ≤ 8 MB（ASTC/ETC2） | 同左 | ≤ 4 MB |
| 每地区棋盘皮肤 + 小动物包体 | ≤ 250 KB | — | — |
| 实时阴影 / 后处理 / 实时透明大面积 | 禁止 | 禁止 | 禁止 |

验收方式：真机打开 Cocos Profiler（`device.numDrawCalls`、`numTris`）连续 20 分钟（GDD 热稳定要求），在“连消 + 3 只小动物同时动 + 夜间”这一最坏组合下截图记录。

## 6. UI 与美术验收标准（清单）

每次交付按下表逐条打勾，附**真机截图/原速录屏 + 构建 SHA + 机型**。只有明确通过的条目才记“已验收”（沿用 GDD 状态用语）。

### 6.1 边界与安全区
- [ ] 在 3 种视口验证：iPhone 16 Pro（灵动岛）、窄屏 Android（中端）、微信开发者工具 iPhone SE 尺寸。
- [ ] 所有可点元素、HUD 数字、棋盘外框都在 `safeArea` 内；右上角不压微信胶囊按钮（读取 `wx.getMenuButtonBoundingClientRect()` 留出区域）。
- [ ] 棋盘外框左右边距 ≥ 24 px（750 设计宽），外框四边完整可见，昼夜两种状态下都能一眼看出边界。
- [ ] 弹层、宝箱、信件不超出屏幕；底部托盘不被系统手势条遮挡。
- [ ] 小动物与彩蛋不进入棋盘外框以内，不遮挡 HUD 和道具。

### 6.2 图标优先的层级
- [ ] 每个按钮/道具/目标先有图标；图标 ≥ 64 px，文字 ≤ 图标高度的 40%。
- [ ] 一屏最多一条说明文字；说明 ≤ 40 字。
- [ ] 数字（步数、数量）用描边或底板，在任何背景上对比度足够（夜间重点检查）。
- [ ] 不出现“第一关”式的演示大面板；不出现技术文字（百分比、下载字节、内部阶段名）。

### 6.3 结算宝箱
- [ ] 宝箱位于屏幕水平正中、垂直中线略偏上（约 45% 高度），宽度占屏宽 40–55%。
- [ ] 宝箱有侧面、木纹渐变、金属包边、开盖火花（对照原版 `treasure.js`）；开盖动作有前摇（轻抖 2 次）→ 开盖 → 物品飞出 → 落入背包图标。
- [ ] 宝箱出现时背景压暗 30–40%，小动物先做完通关反应再让位，周围不放其他同等醒目的元素。
- [ ] 重复点击不重复领取；写入失败有温和的重试提示（GDD 回归场景）。

### 6.4 3D 体积
- [ ] 按钮：有厚度（侧面可见）、顶面高光、底部投影；常态/按下/禁用三态，按下时下沉 3–4 px。
- [ ] 道具与棋子：顶亮侧暗、有接触阴影、有轮廓高光；不是平涂 2D 图标。
- [ ] 角色与线索物品：转镜时无“纸片感”，正/侧/背三方向截图检查。
- [ ] 3D 场景：无 z-fighting、无悬空、无穿模；地面有稳定接地影。

### 6.5 一致性
- [ ] 每个地区只用本区色板（§3.2）+ 全局 UI 中性色；同类元素（按钮、角标、弹层圆角）全游戏统一。
- [ ] 同一物品在地图、棋盘、手帐、分享卡里外观一致（同一模型/同一渲染源）。
- [ ] 光照方向全局统一（左上方主光）；精灵图烘焙光与场景光一致。
- [ ] 字体：全游戏 1 种中文字体 + 1 种数字字体；字号不超过 3 级。
- [ ] 动效时长统一：小反馈 0.15–0.25 s，弹层 0.3 s，转场按 §4。
- [ ] 新地区与老地区放在一起截图对比，看不出“出自两个团队”。

### 6.6 版权与素材
- [ ] 正式包内无电影剧照、海报或截图；加载页为原创渲染。
- [ ] 角色、机器人、地标做过“轮廓对比”——不与已知作品的标志性形象相近。
- [ ] 每个 BGM、音效、字体、贴图都有来源与许可证记录（CC0 或明确免费可商用）。

### 6.7 性能
- [ ] §5.7 预算在最坏组合下达标；20 分钟连续游玩无明显发热降频、无内存持续上涨。
- [ ] 每次构建记录总包体与主包大小；总包 ≤ 24 MiB 为绿线，≥ 27 MiB 为红线（禁止合入新美术）。

## 8. 风险、待确认项与参考资料

### 8.1 风险
| 风险 | 影响 | 应对 |
|---|---|---|
| 包体压不到 24 MiB | 新地区无法上线 | 先砍新区数量（R7 与 R8 合并为一区），再考虑降低模型精度 |
| 低端机帧率不达标 | 活的棋盘卡顿 | §5.5 三档降级，低档用视差背景 |
| 剧情与电影过近 | 版权与口碑风险 | §2.1 原创边界 + 轮廓对比检查 |
| 流量主开不了 | 激励视频不可用 | 设计上本就不依赖广告；免费“+5 步”保底 |
| 微信包体文档口径不一致（20M/30M） | 计划失真 | 用真实上传在 MP 后台核实 |

### 8.2 需要 Funning 确认
1. 地区映射调整（主01 后即进入草甸，§3.1）。
2. 海岛→草甸采用小帆船（§4.2）。
3. 原创人物名：阿芳 / 阿宁 / 老铆；男主身份为“做风筝的少年”。
4. 新增 5 个地区与 26 个新关卡的规模，或先做 R4–R5。
5. 场景设计（新区域）的人选。
6. 激励视频是否保留（默认关闭）。
