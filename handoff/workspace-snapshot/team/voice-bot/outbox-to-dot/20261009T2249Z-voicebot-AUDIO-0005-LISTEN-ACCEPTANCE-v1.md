## 2. 逐个音效的听感验收（PASS / FAIL 标准）

### 当前代码的触发方式（先读这一段）
音效由 `AudioBridge` 在每帧 `update()` 里**只读**观察棋盘状态来触发（不改游戏逻辑），再交给 `GameAudio.play()`。`play()` 的公共规则（对所有音效都成立）：
- 静音（`muted`）或处于后台（`hidden`，Oi 修复版才有）时直接不播；
- 音效没加载到时直接不播（不报错）；
- **同一个音效 60 ms 内只播一次**；
- **同时最多 6 个声音**（按每个 clip 的时长粗略估算，不是精确计数），超过的新请求直接丢掉；
- 播放用 `playOneShot`，已开始的声音没有办法中途停掉。

### S1 普通消除 `sfx_match_normal`
- **什么时候响**：玩家一次操作（交换 / 点特殊块 / 拖炸弹到棋盘）之后，棋盘进入 `run.resolving`，出现**第 1 个 `clear`（消除）动画帧**的那一刻。下落（drop）、洗牌（shuffle）、地区道具（tool）帧都**不出声**。
- **复现**：主线任意关，做一次只消一组、不会连锁的交换。
- **预期**：消除动画出现时响一次，柔和的单个铃音 + 轻风声，约 0.9 s 尾音。
- **PASS**：每次消除只响一次；声音和消除动画基本同步（感觉不到明显滞后，参考 < ~100 ms）；没有爆音、咔哒、破音；连续快速消除时尾音叠在一起但不糊成一片。
- **FAIL**：同一次消除响两次；明显晚于画面；有咔哒/爆破/失真；完全没声（同时看 console 有没有 `[GameAudio] sfx load failed`）。

### S2–S4 连击 `sfx_combo_1` / `sfx_combo_2` / `sfx_combo_3`
- **什么时候响**：同一次操作里的第 2 个 `clear` 帧 → combo_1；第 3 个 → combo_2；第 4 个及以后**每一波**都是 combo_3。玩家下一次操作开始（`action` 帧）时计数清零，从普通消除重新开始。
- **复现**：找一个会连锁 3 波以上的交换（或在炸弹/特殊块后自然连锁）。地区挑战 R5 也走同一套。
- **预期**：一次连锁里依次听到 普通 → combo_1（3 个音）→ combo_2（5 个音，更响）→ combo_3（7 个音 + 和弦垫底，最响）；第 5 波起重复 combo_3。
- **PASS**：每一波都有声音，且**档位逐级上升**（越来越亮、越来越丰富，combo_2/3 明显更响）；下一次操作的第一波回到普通消除，不会接着上一次的档位；无爆音。
- **FAIL**：档位顺序错（比如第 2 波就是 combo_3）；下次操作没清零；长连锁时声音堆叠到破音/嘈杂刺耳；长连锁中间某几波明显缺声（见下面“需要记录”）。
- **需要记录（不算 FAIL，但请写进备注）**：连锁很长（5 波以上）时，因为“同时最多 6 个、按时长估算”的限制，后面的某几波可能被丢掉不响；切后台或动画被取消时，剩下的帧会被跳过，连击声少几下——这两种设计上是可以接受的，请记录实际缺了几声，方便我判断要不要缩短尾音。

### S5 开宝箱 / 领奖 `sfx_chest_open`
- **什么时候响**：棋盘界面开着的时候，主线宝箱的 opened、地区奖励的 claimed、R5 的 claimedRegions（以及以后 0004b 的 r5Claims）里**有一个从“未领”变成“已领”**的下一帧。注意：当前代码不是看接口返回值，而是看状态里“已领数量变多了”。
- **复现**：赢一关 → 结算页点「打开本关宝箱」→ 再点一次（重复领取）。
- **预期**：第一次点：先听到点击声（S6，按钮本身），紧接着开宝箱声（约 2 s，比点击响很多）；重复点：**只有点击声，没有开宝箱声**。
- **PASS**：首领响一次开宝箱；重复点只有点击声；冷启动后直接回到结算页（宝箱已领）时不响；和 R6 已验证的 `windBell +1 / duplicate=true` 一致。
- **FAIL**：重复点也响开宝箱；首领不响；首领响两次；冷启动/重新进棋盘时自己响了。
- **需要记录**：在棋盘界面**以外**（比如海岛主页）领取的奖励，当前代码观察不到，不会出声——这是已知限制，遇到请记录。

### S6 按钮点击 `sfx_ui_click`（音量 0.8）
- **什么时候响**：手指在按钮上**抬起（TOUCH_END）**时。挂了点击声的按钮：海岛导航按钮（`WorldNavigationCanvas` 下除 LabelPlate / Approved* 之外的按钮）、棋盘的「返回」「暂停」、结算面板 `NativeResult` 和选关面板 `NativeStageSelection` 上带文字的按钮（含「再试一次」「打开本关宝箱」）、道具槽（只点不拖）。**棋盘格子本身不出点击声**。
- **复现**：逐个点上面这些按钮；道具槽先只点一下，再拖一个道具到棋盘上。
- **预期**：很短（约 0.12 s）、很轻的一下，比所有其他音效都小。
- **PASS**：每次抬手只响一次；按下不响、抬起才响；道具槽**只点**时响，**拖动（移动 ≥ 12 px）**后放到棋盘上时不响点击声（之后由消除帧出声）；点棋盘格子不响。
- **FAIL**：一次点击响两次（按钮被重复挂监听）；拖道具也响点击；格子也响；明显延迟。
- **需要记录**：场景/界面切换后新出现的按钮，代码每 0.25 s 扫描一次才挂上监听，刚出现的头 0.25 s 内点可能没声；列出任何“应该响但没响”的按钮名字。

### S7 过关 `sfx_level_clear`
- **什么时候响**：棋盘状态从非结算变成 `result.*` 的那一刻，**且本局是赢**（`active.status === 'won'`）。输了不播任何音效（当前没有失败音效）。
- **复现**：赢一关；输一关后点「再试一次」；赢一关后冷启动（重新编译/杀进程重开）直接回到结算页。
- **预期**：赢的时候进入结算页响一次，约 3 s，是最响的音效之一但不刺耳。
- **PASS**：赢 → 只响一次；输 → 不响；输了「再试一次」→ 不响，新一局消除音正常；**冷启动直接回到结算页不响**；离开棋盘再进来（结算页还在）不响。
- **FAIL**：赢了不响或响两次；输了也响；冷启动/重进结算页时误响。

## 3. 静音 / 切后台 / 回前台 / 打断

### 3.1 当前代码实际做了什么（读代码得出）

| 能力 | 当前代码 | 结论 |
|---|---|---|
| 静音开关（UI） | `GameAudio` 有 `setMuted()` / `isMuted()`，静音状态存在本地存储（Oi 版 key：`dot-audio-r1-test-20261009:muted`；Voice Bot 原版 key：`qfl.audio.muted`），启动时读取。**但整个工程里没有任何地方调用 `setMuted()`，也没有静音按钮/设置面板。** | **未实现（只有底层接口，没有 UI）** |
| 切后台 onHide | 监听的是 Cocos 的 `game.on(Game.EVENT_HIDE)`（不是直接 `wx.onHide`，Cocos 在微信里由这个事件转发）。Oi 修复版：置 `hidden = true`，之后的新音效请求全部不播；暂停循环声源；清空发声计数。**已经在播的 one-shot 代码停不掉**（playOneShot 没有取消句柄），它们会不会被系统/引擎掐断取决于微信和引擎。GGbot 原版（v0.2）：只暂停循环声源，不拦新请求。 | **部分实现** |
| 回前台 onShow | `game.on(Game.EVENT_SHOW)`：Oi 版置 `hidden = false`；如果没静音且循环声源有 clip 就继续播。**现在没有 BGM/环境声，循环声源没有 clip，所以这一步实际不做任何事**；后台期间错过的音效不会补播。 | **部分实现（目前只有“恢复允许播放”有效果）** |
| 来电 / 其他 App 抢音频 / 语音消息 | 代码里**没有** `wx.onAudioInterruptionBegin` / `wx.onAudioInterruptionEnd`，也没有处理音频焦点。只能依赖微信切到后台时触发的 EVENT_HIDE/SHOW（来电一般会触发，但不保证）。 | **未实现** |
| iPhone 静音键（响铃/静音拨片） | 代码没有调用 `wx.setInnerAudioOption`（`obeyMuteSwitch` / `mixWithOther`），行为取决于微信和引擎默认值。 | **未设置，按默认行为** |
| 和别的 App 的音乐混音 | 同上，没有设置 `mixWithOther`。 | **未设置，按默认行为** |
