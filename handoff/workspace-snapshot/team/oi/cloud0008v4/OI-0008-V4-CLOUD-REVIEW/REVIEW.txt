三、仍存在的 3 个缺陷与精确复现
所有新场景都以健康场景为底，其它 boot/late canary、LoadScene、自有 CLI 退出/关闭均完整；只新增以下输入。原始行输入见 inputs/new-boundaries/<case>/logs/WeappLog/review.log，CLI 行见相应 cli-output.json。随机 canary token 是审计标记，不是凭证。

A. 高优先级：行内 level tag 前的文字被丢出分类，破坏“整条匹配”。
位置：source/tools/first_open_console_rules.cjs:55-67；source/tools/wechat_first_open_audit.cjs:410-419。
parseLogLine 以任意位置第一个 level tag 切 payload，把此前文字放 prefix；audit 最终只给 classifyEvent(level,payload)，prefix 不检查，也不进入 events-classified.json。
实际输入 / 结果 / 应有结果：
1) <own path> TypeError: actual prefix failure [log] harmless
   prefix-error-before-log → PASS/0；应 FAIL。
2) <own path> TypeError: actual prefix failure [error] [QF-AUDIT-CANARY] <本次token>
   prefix-error-before-canary → PASS/0；应 FAIL，整行含真实错误不能豁免。
3) <own path> TypeError: actual prefix failure [error] <精确通知>；allowlist=1
   prefix-error-before-notice-allowlisted → 特殊放行/3；应 FAIL，前段 TypeError 不能被提示覆盖。
4) OTHER-PROJECT TypeError: unowned prefix failure [log] harmless
   prefix-unowned-error-before-log → PASS/0；应 BLOCKED，无归属也不得静默吞掉错误。
健康与 source-prefix [error] plain fatal diagnostic 对照分别 PASS 与 FAIL。
建议：只剥明确认可的前导协议字段；未知前段须保留在完整待判文本，或标记协议不完整而 BLOCKED。允许 canary/notice 豁免前，应确认整个有效事件无额外未知文字，不能仅检查已经裁掉错误的 payload。

B. 中优先级：CLI 使用同一分类函数，但未做同一等级归一化。
位置：source/tools/wechat_first_open_audit.cjs:415。
自有 CLI stderr 的每一行都设置 level='unknown'，不经过 parseLogLine；因此以下输出且 CLI exit0、其它通道健康时：
5) [console.error] plain fatal diagnostic → PASS/0。
6) [error] plain fatal diagnostic → PASS/0。
场景 cli-error-tag / cli-error-prefix。显式错误等级应 FAIL；若真实 CLI 格式无法安全解释，至少 BLOCKED，不能静默 PASS。普通 [warn] 对照仍 PASS，不能简单将一切 stderr 都算错误。
本次没有证实真实 DevTools CLI 会输出这两个精确格式；已证明候选宣称的多通道错误规则在这两个本地边界下不一致。

C. 中优先级：UTF-8 在 EOF 残缺时未触发协议不完整。
位置：source/tools/wechat_first_open_audit.cjs:198-200 vs :241。
readFrom 检查 decoder.write 的 replacement 字符；stop 对 decoder.end() 的返回值直接 emit，漏掉只在 flush 时产生的 replacement。
7) 完整健康日志结束后，追加 <own path> [log] truncated utf8: 再跟单字节 0xE4（无换行、无后续字节）。
   utf8-truncated-eof → PASS/0，weappLog.incomplete=[]，final-rehash ok=true；应 BLOCKED（不是完整 UTF-8）。
同样位置写 0xFF 的 utf8-invalid-control 正确 BLOCKED。
建议：对 decoder.end() 残余解码结果做同等无效编码检查，或明确检测待完成字节；重哈希证明字节一致不代表编码完整。

完整结果见 results/new-boundaries/summary.json；每个结果目录有原样 verdict、channels、分类事件、console/log/CLI 证据和已冻结 SHA/manifest。
