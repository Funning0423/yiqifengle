# v3 窗台小提示（Funning 2026-10-15 反馈）— 运镜bot

Funning 的反馈是窗口上的光圈挡住了窗外的景色。这一版改成窗台上的小提示：贴在玻璃下沿下面 8 px，不盖住玻璃。
- 文案固定为「出发去看海」。`WINDOW_CAPTIONS` 这个配置还保留，现在只有这一条，默认第 0 条。
- 图标改小：光圈半径 12 px，🍃 14 px。只有图标做呼吸动画：1.6 s ease-in-out，scale 0.9→1.1，透明度 0.6→1。
- 文字 13 px，后面加了半透明圆角底（rgba(20,32,32,0.47)），文字和底不跟着闪，方便看清。
- 可点击区域有两块：提示本身的点击框，至少 44 px 高（117×44）；加上整块玻璃投影出来的矩形。
- 「跳过」按钮和第二次起的快速出门都没有改动（单元测试仍是新增 7 项全部通过，剩下 7 项失败在 5c54f7a 原版上也一样）。

## Patch
`patch/window-tap-exit-v3-sill-vs-5c54f7a.patch`，基线 5c54f7a，6 个文件 +123/−14，包含跳过和快速出门。已在干净的 5c54f7a 上验证 `git apply --check` 通过。完整文件在 `src/`。没有推送，也没有改主线。
- `world-r1/RoomLook.ts`：`WINDOW_GUIDE.glass` 记录玻璃的世界坐标范围，取自 room glb 里的 `env_rear_window_glass`。`window(aspect)` 返回玻璃四个角投影出来的屏幕矩形，以及窗台点（玻璃下沿中点）。
- `RoomExploreOverlay.ts`：提示的顶边放在「玻璃下沿 − 8 px」的位置，左右方向限制在安全区内，下方至少留 96 px。`onWindow()` 判断点击时，点在提示的点击框里或玻璃矩形里都算。

## 投影检查（`scripts/sill_projection_check.py` → `shots/sill_projection_check.json`）
脚本按和 patch 一样的算法计算，用的是默认机位 sitting-room（fov 75）。下表是屏幕像素，y 轴向下：

| 宽高比 | 视口 | 玻璃矩形 | 提示框 | 提示顶边到玻璃 | 和玻璃重叠 | 在安全区内 |
|---|---|---|---|---|---|---|
| 0.46 | 360×780 | x 26–210，y 119–387 | x 70–187，y 395–421（117×26，点击框 117×44） | 8 px | 否 | 是 |
| 0.75 | 390×520 | x 93–215，y 79–258 | x 102–219，y 266–292（117×26，点击框 117×44） | 8 px | 否 | 是 |

- 安全区的标准：左右各留 16 px，顶部留 64 px，底部留 96 px。
- 提示的点击框比提示本身高，上沿会伸进玻璃矩形大约 9 px。这是故意的，因为玻璃本身也可以点。
- 截图里实际渲染出来的提示框和计算值一致，误差小于 0.01 px，见 `*_rendered-box.json`。放大图 `after_sill-tip_aspect0.46_zoom.png` 里可以看到提示在木窗台上，没有挡住海。

**哪些是真的、哪些是模拟：**
- 场景、默认视角和出门镜头都是真实的 5c54f7a 网页构建，点击后调用的是真实的 `__worldIntegration.leave()`。
- 窗台提示是 HTML 模拟层，位置、尺寸和动画都取自上面投影检查的数值，和 patch 一致。
- patch 仍然没有在 Cocos 里编译。
- 「测试包 · 地区流程入口」「地区流程测试」这两块调试条，只是在录制时把运行中节点（LabelPlate、flowTests）的透明度设成了 0，**游戏代码没有改**。
- 改后截图里底部的「向左轻拖」提示也是录制时隐藏的。patch 本身就会在窗台提示显示时把它隐藏。

## 风险和待办
- 文字宽度是按字数估算的（13 px × 1.02 × 字数）。如果以后改成更长的文案，要在 Mac 上确认一下宽度。
- 🍃 是 Label 里的 emoji，微信真机上的字体可能显示不一致，建议换成美术出的贴图图标。
- 需要在 Mac 上编译 Cocos，跑网页构建和微信构建确认效果。
