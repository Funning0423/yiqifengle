# 草甸蝴蝶尺寸核对（运镜bot，2026-10-16，只读调查，无提交）

## 结论（根因）
**Voice Bot 用的 meadowScenePose 是过期的旧值。** 它取自 `/workspace/wechat-game/yiqifengle`（HEAD 5c54f7a，旧 checkout）里的 MeadowSceneData.ts：
position [9,19,42] → target [0.327,5.509,-15.817]。
而 PR #58 @0b1181d（以及 edc65d5、2a216a0、41f47f7）里的竖屏镜头早已改成（fc563b2 引入）：
**position [0,24,45] → target [0,4,4]**，FOV 相同。
用游戏镜头投影 v7.5 GLB：**meadow_butterfly_00 在 8s 循环的 0.2–2.7s 横穿段完全在画面右侧之外**（中心 x≈163%–228% 屏宽，距镜头 ≈12.7–13.2m），240 帧里 0 帧可见。录屏里看到的 4–6px 蝴蝶是 **butterfly_01/02**（远处那两只），不是 00。所以 40s 时 00 根本不可能在画面里，与循环相位无关。

我的投影脚本用旧镜头复现了 Voice Bot 的数值：最大 9.28%，t=2.17s（第 66 帧），距离 7.85m，540 宽时 50.1px。完全一致，可以证明脚本可靠。

## 预期尺寸（游戏镜头，375×812）
- butterfly_00：0.2–2.7s 不可见；只有 ≈6.7s 离场时有 2 帧擦边。
- butterfly_01：全程可见，最大约 13.8px（3.7%）。butterfly_02：最大约 12.9px。翅膀侧向时更小，和录屏的 4–6px 对得上。
- 如果镜头对了：按旧镜头算，00 在 375 宽下约 34.8px（9.28%）。

## 修复方案
1. **（推荐）移动 butterfly_00 的路径，不改镜头。** 把 00 根节点的关键帧整体乘上刚体变换 X = G·S⁻¹（S 是旧镜头的相机矩阵，G 是游戏镜头的）：
   ```
   [ 0.9889  0      -0.1483  -2.6701]
   [ 0.0334  0.9743  0.2226  -4.1631]
   [ 0.1445 -0.2251  0.9636   7.5072]
   ```
   旋转也要左乘。这样在游戏镜头里的画面和 v7.5 预览完全一样：宽 8.3–9.3%，中心在离画面底部 26–30% 的高度。例：t=1s 的点 [7.40,15.66,34.72] 变成 ≈[-0.50,19.07,38.51]。
   缺点：离地会更高（镜头在 24m 高），浮空感更强。也可以只保证“距镜头约 8m、在镜头前方偏下”，把路线重做得贴地一些，再用 `proj.py`（把 poses 换成游戏值）验证。
2. **把 meadowScenePose 改回 [9,19,42]：不推荐。** 游戏构图、棋盘留白和天空区（鸟、大云）都是按 [0,24,45] 排的。
3. 不管选哪种，Voice Bot 之后的预览都必须从 PR 分支（0b1181d 或更新）读 MeadowSceneData.ts，不要再读 yiqifengle 的旧 checkout。鸟和大云被棋盘挡住，很可能也是同一个原因，建议一起用游戏镜头重新核对。

脚本：`proj.py`（00 号，两套镜头）、`other.py`（三只蝴蝶 + X 变换）。数据源是 v7.5 候选 GLB；动画按线性插值，未执行 Blender。
