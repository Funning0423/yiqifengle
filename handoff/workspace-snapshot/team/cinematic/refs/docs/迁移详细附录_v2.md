## C 存档与身份合同

1. 原主线权威键 forest-v33-journey 与 SAVE_VERSION 3 保持；兼容 forest-v3-progress、forest-v3-completed。海岸 forest-coast-content01 与引导 forest-coast-beacon-guide01 同样保留。新引擎不能仅改用默认 localStorage 然后声称旧档自动继承；微信 adapter 要实测原 wx 存储键与值类型。
2. 第一阶段用复制样本或独立测试 namespace，禁止写唯一真实存档。迁入时先备份、校验、转换到内存、读回验证后再提交；失败保持旧权威数据，不删除损坏原件。
3. 保留原 12＋9 的数字索引与奖励身份。若新增稳定 ID 注册表，显式列 legacyIndex ↔ levelId，对现存档只做兼容映射；不能把数组插入当作无风险扩关。新候选独立 catalog/packId，主04候选记录不得抹掉原成绩。
4. SceneFlow 只发 progress 查询和完成事件；唯一 SaveService 决定可提交状态。领取带稳定 rewardId／transactionId，重复回调、切后台和旧 Promise 不二次发奖。是否已存在相应事务字段按代码核对，新增字段先做兼容测试。
5. 杀进程后的棋盘续局在旧版尚未实现；引擎迁移不把它算已完成。若启用 R3 checkpoint，另测恢复校验、版本不兼容、一次结算和旧活动会话续玩的边界。

## D 资产与动画合同

Grokbot 当前拥有美术源。交付 .blend 原件、贴图源、许可／来源说明、glTF 2.0／GLB 首选导出，FBX 为需单独往返验证的备选。Cocos 官方支持 FBX 与 glTF，但 Blender 节点材质、修改器、约束和布料缓存不因此获得无损导入保证。[D1][D2]

新导出约定 1 Cocos 单位对应 1 米，Y 向上；前向、原点、根变换、骨架 rest pose 和单位转换写 manifest。B 的身高与身体比例必须从认可参考测量并记录，不能为凑单位重新设计比例。先拿单位立方体与 B 副本验证轴向和尺度；任何 apply transform 在副本且需骨架／动画往返检查。主角／门／椅／机器人使用同一尺度基准。

黄裙和白围裙独立对象／材质／可控骨链或经验证的烘焙变形；明确腰部固定区和围裙双角。变形骨初始预算≤60，每顶点≤4归一化权重；非变形控制骨可留源但导出清单明确。初版导出角色近景≤25k三角，远景另测轮廓，不靠更换比例降面。每资产记录 meshes/materials/textures/triangles/bones/decoded texture estimate。预算是项目起点，超预算需数据和画面证据，不能静默削掉关键衣层。

固定动作先交一条连续参考，再拆 sit_idle、stand_up、turn_left、walk、stop、door_open、enter_close、sit_down 等建议语义。名称可协商，但映射、时长、帧率、是否循环、接触事件都必须写明。建议 30 fps 烘焙采样，快速接触段可测 60 fps；不是强制运行帧率。女主 root 位移只能由动画或控制器其一驱动，禁止叠加两次。起身根曲线和椅锚点共同校准；手到门把与门轴旋转使用同步事件，不能靠随机伸手碰到。

碰撞代理由 Grokbot 随资产提供并注明用途。初始类别包括 body capsule、地面、椅面／靠背、门／门框、手／前臂接触代理。视觉角色、骨骼、代理必须能一同显示核对；大胶囊只处理导航边界，不能冒充衣手接触完成。先用离线动画避交和有限接触修正，之后才测少量衣角二级运动。Builtin 只检测接触，不做刚体响应；如需刚体后端，在微信包体与兼容性评估后选择，不先默认 PhysX 大包。[D3]

### 语义锚点与所有权

以下均为拟定接口，不代表现源已有节点：scene_root、spawn_outside、seat_anchor、seat_back、door_hinge、door_handle、doorway_exit、return_path、interaction_shells、interaction_bells、interaction_stars、robot_root、board_safe_zone。提供 anchors.json，逐项绑定真实节点路径、局部矩阵、所属区域、包 hash 和是否实现；missing 可以明确写缺失，不能填虚假路径。

拟定目录：art-source/grokbot/ 放源资产清单和导出说明；cocos-game/assets/art-imports/ 由指定资产集成人单写，接收 Grokbot 冻结导出并维护 .meta；cocos-game/assets/scripts/core/、adapters/、tests/ 由 dot 写；cocos-game/assets/scenes/ 与 prefab 由 dot 集成人单写，Grokbot 通过导出场景／布局说明交付，不与 dot 同时改 scene/prefab/.meta。

艺术意图、材质／灯光校准由 Grokbot决定并交证据；dot只做已约定适配和性能档参数。若需改拓扑、UV、材质或重新烘焙，退回 Grokbot，不私改资产源。现有 dot Stage1/2 和服装研究仅档案，未经接纳不塞入切片作为成品。

## E 场景与渲染运行合同

区域 key/id 固定 tide/0、meadow/1、sky/2。boot 只含启动UI和必要配置，shared 共享角色／通用UI／声音，tide_room／tide_island／meadow／sky 分 Bundle。保留 puzzle 逻辑与每区域的棋子外观绑定；36或更多关只加载配置，不复制完整场景。海岛灯塔先用于技术压力片段，天空之城仍是最高美术验收重点，草甸／天空城不能被技术顺序默认为取消。

建议边界：LevelCatalog.resolve(levelId) → 纯规则配置；SceneFlow.enter(regionId, cameraMode) → load token；AssetResolver.resolve(assetId, quality) → 唯一资源引用；InteractionService.dispatch(id, action, stateVersion) → 结果与显示事件。上述为拟定接口，具体代码签名在 MIG-002 锁定后出接口版本，不臆造现成 API。

CameraDirector.fixed 与 motion 两线共享稳定世界坐标。角色／岛／海／云不随相机另算空间；门往画面左开，相机从右绕行，镜头提起能见路径海景。相机轨迹由 dot 接口实现，构图需要 Grokbot 与用户验收；不修改 B 身材解决读图问题，地图角色过小要通过镜头／构图调整。

先选简单可测的移动端渲染配置。静态物体用光照烘焙或有限环境光；近景主角必要动态影，远景减少或关闭动态影。Planar 只适用平面接地，不能在斜坡／椅面上冒充真实投影；ShadowMap 分辨率、PCF 和覆盖范围分别测。水面／玻璃／草片／云共同计过绘；不让多个全屏透明层抵消实例化收益。[D4]

LOD 优化可见网格细节，不自动减少所有脚本／骨骼求值。远处人物另显式降动画更新与二级运动频率，保证节奏和遮挡无明显跳变。重复静态物体共享网格和材质才适合实例化；透明排序与非均匀缩放法线另验。骨骼实例化限预烘焙适配路线，主角色实时骨骼不能强开同一路径。[D5][D6]

贴图先按 512／1024，角色关键图按收益允许 2048；计算解码／GPU格式内存，不能把低质量 JPG 文件变小等同显存降低。压缩格式按设备能力选择，ASTC 要真机测并保兼容回退。AA 逐目标微信图形路径比较无 AA、支持的 MSAA 或 FXAA；记录发丝、裙边、门框闪烁和 GPU 成本，不能只在截图上看一次。[D7]

资源退出流程：取消旧加载 token → 结束输入与音频／计时器 → 移除场景实例 → 按引用释放区域专属资源 → 延后检查稳定内存。共享角色／UI只由共享资源服务计数，禁止多个 bundle 独立释放同资源。下载、解析、实例化、shader首次编译分别打点；关键下一段提前预载。Bundle load 与单资产 load 是不同步骤，按真实依赖图消除重复下载。[D8]
