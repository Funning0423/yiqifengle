# 咦 起风了 Cocos 迁移执行方案

版本 2.0  ·  2026 年 10 月 8 日  ·  执行对象 dot 与 Grokbot

用户已决定采用 Cocos 作为后续 3D 工程方向。现在先建立独立迁移工程与资产契约，优先验证最重的角色、房间和岛屿片段；通过基础验收后按模块迁入完整游戏。本文件取代旧方案中“Cocos 仅为备选”的表述。

当前交付是方案和任务定义。Cocos 编辑器、工程和微信构建尚未核实安装或完成；Grokbot 尚无实际读取回执。原 21 关、B 比例、两条镜头线、v3 存档与原 AppID 都是迁移约束。

## 1 为什么现在迁移

现自研 WebGL1 路径由 CPU 逐顶点计算骨架与衣物，再上传动态顶点；人物接触修复还增加多轮查询与求解。随着近景动作、独立衣层、场景互动和更多 3D 内容叠加，主线程、数据搬运和长期维护成本成为主要风险。手机预算尚未通过，不能声称已有证据证明必然运行不了。

WebGL 可以做 3D，Cocos 的微信输出仍依赖平台图形能力。此次选择是将蒙皮、场景、资源和构建交给成熟框架，同时重做高成本算法；把旧逐顶点路径照搬进新引擎不会自动降负载。Cocos 提供预烘焙和实时骨骼方案，两者均可在 GPU 完成蒙皮。[1][2]

## 3 先通过最重片段 再迁完整游戏

首个 vertical slice 必须使用有代表性的 B 比例角色与独立黄裙／白围裙、真实椅子和门、房间内外及一小段岛屿。简化方块可验证构建，但不能作为性能或画面通过的证据。

| G5 替换与回滚 | 复制存档迁移和旧版回退演练、全量回归、可复现构建均通过；主整合者记录接纳，用户确认发布目标后才替换对外版本。 |

### 片段必须看见的问题

- 真实坐有靠背椅，起身与转身有重心和脚底支撑；无滑步、突然加速、过大首步或根节点下台阶。手臂自然下垂，只有触门才伸手。

- 门向画面左开，相机从右侧绕行；世界、海面和云保持统一坐标。返回室内完整，进门顺手关门，两线速度与流程一致。

- 围裙双角可轻摆脱离黄裙并回落，黄裙更重。近景逐帧查手／肩／裙／椅／门接触，不靠撑臂、膨胀衣服或换机位隐藏穿模。

若任一关口失败，留在独立 Cocos 候选修复，不把新包替换旧包。若减掉必要动作／衣层才能达预算，视为尚未通过，先调整资产、动画策略或画质配置。



## 4 动画 碰撞与区域资源

### 将确定动作的成本前移

Grokbot 在 Blender 完成绑定、接触修正和固定动作烘焙；首片优先完整烘焙骨骼播放。Blender 布料模拟缓存不能直接当 Cocos 可播放资产，需变成经验证的骨骼动画或另行验证的格式。当前 B 基底无 Actions，不能写成动作库已存在。[2][3]

仅在需要 IK、混合或少量衣角骨修正时启用实时骨骼路径并测成本。不能在预烘焙蒙皮开启时假定随意修改骨骼节点就会生效；也不高频切换两种模式。主角色可用实时骨骼＋GPU 蒙皮的单独质量档，低档必须保留已烘焙的轻重层次。[2]

移动用胶囊／简化地形代理；门、椅和手部用贴合形状的少量代理与动画接触事件。胶囊不能代表全部衣手碰撞，离线修正仍必须做。禁止默认全身逐三角全量接触求解；Cocos 3D 刚体功能也不等于开箱即用的通用布料。[4]

### 按区域加载 按预算保留

| 内容 | 第一版执行策略 |
| --- | --- |
| 资源分层 | boot 最小启动；shared 唯一共享资源；tide_room／tide_island／meadow／sky／puzzle 按需 Bundle。离开区域释放专属引用，禁止同时常驻三区。 |
| 关卡规模 | 规则／关卡数据与美术分离。原 21 关稳定身份保留；R3 已冻结 36 个数据／API 候选，新增菜单入口仍为 0；不把候选等同可玩版本，也不按每关复制场景。 |
| 模型与重复物 | 角色近／远 LOD 保 B 比例；岩石、草木等按材质实例化或批处理；透明草云控制过绘。实例化不是所有对象无条件合批。[5] |
| 贴图与光照 | 先 512–1024 贴图，关键角色按证据用 2048；贴图格式按真机压缩兼容选择。静态光照优先烘焙；近景只保必要动态影，低档验证平面接地影。[6] |
| 水与抗锯齿 | 单海面材质控制反射成本；先避免多层全屏透明。AA 与渲染比例逐设备比较，不能假设所有微信路径都支持同一 MSAA 设置。 |

Bundle 是资源组织方式，微信分包是发布配置，两者需正确映射。远端只放合规资源，不用远端包执行脚本；Drive 不是运行时 CDN。具体平台包体／域名／缓存限制在锁版本时核官方与当前后台，不照抄旧数字。[7][8]



## 5 真机验收与初始预算

以下全部是待验证的项目目标，不是测得成绩，也不是微信平台硬限制。G0 记录中端 Android 的具体型号、系统、内存和微信版本；与 iPhone 16 Pro 使用相同回放、亮度、网络和画质档。不能用桌面、开发者工具或离线视频代替。

| 指标 | 首轮目标与测法 |
| --- | --- |
| 帧时间 | 16 Pro 标准档目标 60 FPS：中位帧间隔≤16.7 ms、P95≤20 ms；中端 Android 保底档目标 30 FPS：中位≤33.3 ms、P95≤40 ms。场景内反复出现>100 ms停顿算失败。 |
| 主线程与 GPU | 16 Pro 主线程工作目标≤10 ms，逻辑＋骨骼／轻物理≤6 ms；GPU 目标≤12 ms。两者不直接相加，GPU 不可观测时标未测，不能用JS耗时代替。 |
| 可见资源 | 首片起始目标≤120k可见三角、≤80 Draw Call；角色LOD0≤25k三角、≤60变形骨、每顶点≤4权重。数值需按真实导入／真机证据再锁。 |
| 内存 | 先控活跃纹理估算≤64 MiB，记录可见的进程／引擎／缓存峰值及口径。20次往返释放后，稳定窗口内存不持续增长；与第1次比目标≤10%且无OOM。总峰值门槛G0实测后锁。 |
| 加载与退出 | 控制网络20 Mbps／80 ms RTT，首可交互目标≤8秒，缓存热启≤3秒、预载后切区≤1秒。退出关卡不留棋盘或音频；包失败可取消／重试，不黑屏。 |
| 持续运行与发热 | 同条件连续20分钟，末5分钟帧时仍过门槛；记录耗电、热状态、可用的温度数据及降频迹象。不能仅凭桌面或主观手感说“不发烫”。 |
| 故障与恢复 | 未缓存断网、下载中断、已缓存离线、弱网重试；动作／结算／下载时切后台再回来；重复点击和触点取消；不重复领奖、不丢档、不双播声音。 |

每条记录含 build／commit、资产包 SHA-256、引擎与基础库、设备、画质、测法、原始帧时及原速录像。结果必须分通过、失败、未跑；完整动作逐帧视觉结论和用户美术认可单独记录。
