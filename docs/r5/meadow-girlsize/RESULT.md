# r5 草原女孩太小：四个方案（仅准备，不合并）（cine/r5-meadow-girlsize-options）

基线 `gbt/r5-integrated-b07-wip` @ bc81575f。现状：草原 M1–M4 都用 boardPose 'default'（meadowScenePose PORTRAIT，pos [9,19,42]，fov 49.4°），这是一个固定的全景机位，所以她越往里走就越小。

代码：`creator-build-project/assets/scripts/region/MeadowGirlSizeOptions.ts`，开关 `MEADOW_GIRLSIZE_OPTION='off'`，**未接线**，运行时零影响。
- 三个方案都保留原机位的朝向，只改位置或 fov。
- 她的包围盒（girlBoxPt）放在 UI 让出的区域里尽量放大：区域四周各内缩 13 pt；`zone:'left'` 表示她站在工具栏左侧。
- 选 left 是因为这样镜头位于她背后偏右，符合 F7b 方向，从 M4 出发走 08→09 时不会反向。用 right 侧时，手机上她能大到 14.4%，但镜头会跑到她左边 2°。

## 方案
- **A 落点拉近**：fov 不变，相机沿原视线方向推近，到她刚好填满区域为止。
- **B 收窄 FOV**：tan(fov/2) ÷ 1.5（49.4° → 34.1°），相机相应后撤到同样构图。透视更平，离几何更远。
- **C 到位后小推近**：落板时先在 1.45 × A 的距离（C 起点），然后 1.6 s smootherstep 推到 A。
- **D 地平线球面弯曲**（参考 /workspace/b05/research/acnh/REPORT.md §5）：
  - 构图同 A，但镜头再俯 10°；
  - 世界按到她的水平距离做**径向（球面）弯曲**：`y -= ((x-cx)² + (z-cz)²) / (2R)`，R = 120 m，弯曲中心 = 她所在节点 / 自由视角的环绕中心；
  - 她本人和天空穹顶不弯；
  - 参考函数是 `meadowBendDrop()`，参数在 `MEADOW_GIRLSIZE.dPitchDeg / dBendR`。

## 方案 D：地平线球面弯曲（补充）
**板上（三种屏，见 `{M1,M4}_{屏}_D`）**
- 身高：390 为 10.8%、360 为 9.0%、768 为 22.2%。比 A 略小，因为多俯了 10°。
- 弯曲把风车所在的坡顶"压"回画面：不弯时，同样俯角下风车顶会被推出画面（ndc y 1.14），R = 120 时它回到 A 的位置（0.25–0.84），画面上方出现弧形坡顶和天空，有动森那种感觉。
- 离几何：390 为 14.8–15.0 m，768 为 7.1–7.9 m。头和胸都无遮挡。
- **问题 1：M4 出现空背景**。390 上 void 为 0.02，360 上为 0.04：坡顶弯下去以后，穹顶下方露出没有几何的空隙。§4 要求"背景完整"，所以这一项**目前不达标**，需要把天空穹顶往下延伸，或者给地形边缘加裙边。
- 混合：跟随 → 板进入 M4 时 90.1°/s（A 为 85.1），板 → 跟随离开 M4 时 56.2°/s（A 为 32.3），因为多俯了 10°。位置差 15.0 / 12.7 m。镜头方位为 −20.7°（手机）/ −25.1°（768），在她右后方，F7b 语义满足。
- 08→09 时长不变。

**自由视角（转视角是否露馅）**
图：`free_yaw{0,90,225}.png`（每张：左 = 不弯 / 中 = D / 右 = 只弯 z 的圆柱对照），`free_turn_sphere_vs_cyl.png`。条件：M1，距她 9 m（规范草稿上限），俯 25°，390×844。
- 用 `horizon_tilt.cjs` 量化：取镜头前方 30 m、左右各 ±12° 的地面点比较。
  - **球面版**：0°、45°、90°、225° 四个方位的下沉都是 2.03 m，地平线倾角都是 0°，转到哪个方向看起来都一样。
  - **圆柱版**：0° 时下沉 1.87 m；90° 时只剩 0.16 m（弯曲消失，地平线回到平地的远处）；45° 和 225° 时左右下沉为 0.47 / 1.57 m，**地平线倾斜 5.1°**。也就是说，一转视角就露馅。数据见 `horizon_tilt.txt`。
- 自由视角下她的身高：9 m 时 21.9–23.2%；14 m（当前 ORBIT_LIMITS 上限）时 14.1–14.9%。弯曲本身不改变她的大小；它的作用是让近距离、往下俯的镜头仍能看到风车和天空。
  - 例：方位 0°、9 m 时，风车 ndc y 从 1.35（出画）降到 0.97（入画）；14 m 时从 1.20 降到 0.87。
- 镜头正下方地面的下沉：9 m 时 0.28 m，14 m 时 0.67 m（R = 120）。这只会让离地距离变大（9 m 时 4.06–5.38 → 4.34–5.60 m），自由视角的下限 3.2 / 4.3 m 不受影响。
- 风险：14 m 且方位 90° 时出现 void 0.06（远处地形边缘下沉、露出穹顶下方）。自由视角上限越大，R 就要越大，或者穹顶要越往下延伸。建议把 R 和距离挂钩，按 ACNH 的做法：镜头越低 k 越大。

**性能开销与工程影响**
- 顶点着色器：每个顶点多 1 个 uniform（vec4：cx, cz, 1/2R, 开关），约 5 条 ALU（2 次减法、2 次乘加、1 次减法），没有纹理读取。
  - 草原 GLB 共 78 492 个三角形，按顶点数量级估算，每帧多几十万次 ALU，在手机 GPU 上可以忽略（< 0.1 ms）。
  - 片元着色器零开销。
- 必须接同一个 chunk 的材质：地形、草（包括 GPU 草叶动画）、水、道具、粒子、阴影投射 pass（不弯的话阴影会错位）、描边 / 边缘光 pass。
  - 漏接一个，就会出现"飘起来"的物件，这是最主要的工程风险。
  - 估计要改 builtin-standard 和 toon 两套，再加上自定义草和水的 effect。微信小游戏在不同 macro 组合下都要重新编译 effect。
- 视锥剔除：弯曲只会往下压，所以每个物件的包围盒要向下扩 maxDrop。9 m 自由视角下，100 m 处约 42 m。否则远处物件会被错误剔除。
- 点击 / 射线：点地寻路用的是未弯曲的碰撞体，离她 r 米处的视觉误差等于下沉量（10 m 处 0.42 m，20 m 处 1.7 m）。需要在射线上做反向修正，或者只允许点击近处。
- 自由视角影响：径向弯曲以她为中心，绕她转多少度都完全一致，不会露馅（见上）。拉远时，远处下沉更快，需要 R 随距离增大，或穹顶下延；拉近时影响很小。
- 与 A/B/C 的关系：D 不能单独让她变大，变大来自 A 的构图；D 的作用是允许镜头更俯 / 更近时仍然保留风车和天空。可以和 A 叠加用。

## 对 08→09 的影响
- **A / B**：时长不变。只换板机位，BLEND_S 0.6/0.8 s 不变，B-a 步行 M4→M6 也不变。出发时板→跟随的位置差从 52.8 m 降到 11.2 / 17.9 m。
- **C**：08→09 时长同样不变，但每次到板会多一段 1.6 s 推近。如果和到达提示、托盘入场同时发生，会有两层运动叠加。如果在推近中途离开，要从实时机位混出，否则会跳。

## 对 F7b 的影响
- F7b 测试的输入（legacy meadowScenePose / 站位线）没有动，**测试结果不变**。
- 按 F7b 的语义（镜头保持在她右侧、不跨到左侧）：三个方案在 M4 出发时镜头都在她右后方（−15°～−23°），符合要求。
- 如果改用 right 区，手机上会变成 +2.2°，跨到左侧，不建议。

## 风险 / 注意
- 手机上她站在画面左下角（包围盒 x ≈ 13–50 pt，ndc ≈ −0.85）。这超出跟随机位的 frameLimits maxAbsX 0.7，但板机位本身没有这条限制。原因是中间带被托盘、底部被工具栏占满，竖屏只剩工具栏两侧能放下她。
- B 在 M4 时风车和铃架占满上半屏，透视明显压平，"草原全景"的感觉弱了很多。A 保留了原透视。

## 推荐
**A（落点拉近）** 为首选（D 作为 P1 美术增强可后续叠加在 A 上，但要先解决 M4 的空背景和全材质接入）：
- 手机上 10–12%（约 1.9 倍）、768 上 22%，UI 间距 ≥ 14 pt；
- 透视和风车构图保持不变；
- 混合距离最短，08→09 时长和 F7b 都不受影响。

如果想要"到了以后被吸引过去"的感觉，可以在 A 的基础上加 C 的推近，但需要先把板 UI 入场节奏对好。B 只适合想要长焦感的时候。
