# r10 规格：室内环绕 → 房间视角（只做设计，不含游戏代码）

- 基线：`cine/r5-room-orbit-r7-wip` @ **d1a491c1**（FreeOrbit = r8 代码 + 文档）。r9（b3d2cbd6 / 代码 153f69a8）只在 Mac 上，这里看不到，下文中“r9 式”是近似模型。
- 数值检查：`tools/region-nodes/r10/r10_check.cjs`（模型 `r10_model.cjs`，图 `plot_r10.py`）。
  运行：`QF_TYPESCRIPT_MODULE=<typescript> node tools/region-nodes/r10/r10_check.cjs [--variants] [--json out] [--trace out]`，全部通过时 exit 0。
- 对比图：`previews/运镜bot/r5-room-orbit-r10-spec/COMPARE_r9_vs_r10.png`。

## 0 结论（先看这里）

1. **整个镜头位姿是输入的纯函数** `pose(θ, pitch, dist)`。拖动、惯性滑行、松手后都不加时间域跟随器。所以：取景没有滞后；没有过冲；与帧率无关。
2. 位置、瞄点、取景**共用同一个** `w(θ)` 和同一条过渡带。
   - 过渡带：核心区 [330°, 14°] 外两侧各 **W = 50°**。
   - 曲线：**smootherstep**。
3. 瞄点 = lerp(她的取景中心点, roomGaze, w)，镜头位置 = lerp(环绕镜头, 房间中心, w)。
   - 选 **方案 A**：证明 w ≤ w* 时她一定在画面内，并重新定义过渡带验收口径。
   - 实测 w* = 0.317（9 组 pitch/dist 中的最小值），验收门槛定为 0.28。
   - 方案 B 不可行，原因见 §3.2。
4. 墙限臂长 `roomArm` 改成解析平面包络（p-norm 超椭圆，k = 3）。
   - 精确臂长在侧墙边是“贴墙滑动”：每度约 0.3 m。r9 失败的大头在这里（见 §2.3、§6 中 envK = 0 一行）。
5. 惯性滑行改为精确指数积分，消除帧率依赖：现 `step()` 在 30/60/120 fps 下终点差 2.09°，r10 为 0.000°。
6. **无法同时满足的折中（明确说明）**：
   - 90°/s 松手后的惯性滑行，在过渡带内的镜头附加角加速度 = **228 °/s²**，超过 110 °/s² 时间上限。
   - 方案：把惯性滑行归为“输入运动”，用曲率门槛约束，不用 110 时间上限（§5.1）。
   - 30°/s 松手后的滑行为 78 °/s²，满足 110。
   - 镜头线加速度不设门槛，只报告（§5.2）。

## 1 速度无关的门槛（修正用户推导）

用户写的是 a(θ) = Δ·s((θ−θ0)/W)，推出 a'' = Δ·s''/W²，再要求 |d²a/dθ²| ≤ κ = 110/30² = 0.1222 /deg。

- **门槛形式正确**：附加角加速度 = a''·ω² + a'·ω̇。拖动时 ω̇ = 0，所以“30°/s 时 ≤ 110 °/s²”等价于 |a''| ≤ κ，而且对任何 ω 都按 ω² 缩放。90°/s 时同一曲线自然是 9 倍，这是设计结果，不是缺陷。
- **推导有误**：在过渡带里，Δ 不是常数。镜头在核心外已经无法继续环绕，“看她”的方向与房间视角方向之间的差 D(θ) 随 θ 大约 1:1 增长（核心边缘处 D ≈ 0，带外缘 70–90°，正是 r9 的 Δ）。
  - 设 φ = φ_h + w·D，D ≈ u·W（u = (θ−θ0)/W），则

    **φ'' = (s''·D + 2 s'·D′)/W² = (u·s''(u) + 2 s'(u)) / W**

  - 曲率随 **1/W** 缩小，不是 Δ/W²。漏掉的 2s'·D′ 项在带中段占主导。
  - 所需带宽（κ = 0.1222）：

    | 曲线 | max\|u s'' + 2 s'\| | 需要 W |
    |---|---|---|
    | smoothstep | 6 | ≥ 49° |
    | smootherstep（C2） | ≈ 4.62 | ≥ 37.8° |
    | bang-bang：令 (u² s')′/u 取 ±c | c = 1/(√2−1) ≈ 2.414 | ≥ 19.8° |

    - bang-bang 的形状：s' = c/2（u < 1/√2），之后 s' = c(1/u² − 1)/2。
    - 用户的 smoothstep Δ90 → W ≥ 66.5°、“s'' max 4 → W ≥ 54°”这两个数，都是在 Δ 取常数的假设下得到的。
- **真实三维几何还会偏离这个一维模型**：镜头向房间中心移动，她的方位角会额外变化约 26°，而且瞄点 lerp 是弦而不是角。所以最终以 `r10_check.cjs` 的数值为准。实测：
  - smootherstep W50：带内最大曲率 0.048–0.083 /deg，全扫描最大 0.0913 /deg（在核心内 θ≈10°，来自包络推近）。✅
  - bang-bang：入口处的加速度阶跃在三维里不再被 D(0) = 0 抵消（核心边缘 D₀ ≠ 0），曲率 0.65 /deg。❌ **淘汰**。
  - smoothstep W70（用户方案）：曲率同样 0.0913 /deg，但 w* = 0.282，余量太小。
  - **选 smootherstep W50**：C2，入口没有加速度阶跃，W 比 70 更窄，所以 w* 更大。
- **110 °/s² 时间上限**只用于非输入运动：settle/return、seed fade、捏合；松手后的惯性滑行见 §5.1 的折中。快甩（flick）按曲率门槛验收，要求无过冲、无跳变：视角每输入度的转角 ≤ 1.5，且始终与手势同向。

## 2 位姿定义（纯函数）

记号：LO = LOOK + lensCentreOffset，即 `orbitPivot(FEET)` + `R.lensCentreOffset`；u(ψ, p) 为臂方向。

### 2.1 权重
- e(θ)：θ 在核心 [edgeA, edgeB] 外的角距离（取近的一侧，side = ±1）。
- w(θ) = smootherstep(clamp(e/W, 0, 1))。核心内 w = 0；带外 w = 1，即纯房间视角，360° 自由看。

### 2.2 环绕方位饱和
ψ(θ) = θ（核心内）；带内 ψ = edge + side·satW·g(e/satW)。其中 g(t) = t − t²/2（t < 1），否则 g = 0.5。
- 这是 C1，斜率从 1 均匀降到 0。镜头方位最多超出核心 15°，不再贴墙走。

### 2.3 环绕镜头（替换 roomArm）
- 水平臂长 ρh = softMin(dist·cos p, E(ψ))，softMin 用 FreeOrbit 现有的 softK = 8。
- E 的定义：1/E^k = Σ_i (max(0, n_i·(sin ψ, cos ψ)) / g_i)^k，k = envK = 3。
- 三面墙：东、西、北的内缩墙，g_i 是从 LO 到各墙的距离（keepInside 内缩 insetM 0.2）：
  - g_E = 0.634 m
  - g_W = 1.116 m
  - g_N = 3.228 m
- 性质：p-norm ≥ max-norm，所以 E ≤ 精确墙臂长，**镜头必在内缩盒内**（构造保证，不靠夹紧）。超椭圆曲率有界。
- 镜头高度沿用 `softClamp(LO.y + sin p·ρ, box.min.y + inset, min(box.max.y − inset, lensMaxY))`。
- orbitLens(ψ) = LO + u(ψ, p)·ρh/cos p，高度如上。

### 2.4 混合
- herAim = LO 侧取景中心点：`frameCentre(orbitLens, unit(HER_C − orbitLens), LOOK, framePts)` × |HER_C − orbitLens|。
- gaze = R.center + roomViewDir(θ, p, R)·gazeM，gazeM = 1.9。
- lens = lerp(orbitLens, R.center, w)
- aim = lerp(herAim, gaze, w)
- view = unit(aim − lens)，roll-free。
- R.center 与 keepInside 都是凸集，lens 是盒内两点的插值，所以离墙距离由构造保证（实测 ≥ 1.04 m）。

## 3 取景：方案 A

### 3.1 证明与口径
- w = 0 时就是核心取景。全扫描下她身体到安全框的最大 NDC 为 0.874 < 0.9。
- 位姿对 w 连续（§2 全是连续函数），her centre 的 NDC 也对 w 连续。所以存在 w* > 0，使 w ≤ w* 时她的中心在画面内（|NDC| ≤ 1）。
- 数值实测：w* = **0.317**（9 组 pitch {−14, 10, 26} × dist {3.35, 2.6, 1.9}，θ 步长 0.25° 中的最小值）。
  - smootherstep 下 w = 0.317 对应 u ≈ 0.40，即进入过渡带约 **20°**。
  - 在 pitch 10 / dist 3.35 的曲线上，中心 NDC 只穿出一次（见图第 4 栏），之后单调远离。
- **新的过渡带口径**：
  - w ≤ w*（门槛 0.28，留 0.037 余量）的帧，她的中心出画帧数 = 0。
  - w > w* 的帧属于“交给房间视角”，不计入出画。
  - 不再统计“整个过渡带的出画帧”：r9 的 11192/15905 这种口径，在任何保留 360° 自由看的设计下都必然失败，原因见 3.2。
- 身体安全框（0.9）的 w*_safe ≈ 0.01，即一进带身体边缘就可能出安全框。原因：dist 1.9 时人物占满画面，核心边缘已经 0.874。只报告，不设门槛。

### 3.2 为什么不选方案 B（roomGaze 永远框住她）
- 带外 w = 1 时视角 = roomViewDir(θ) = −u(θ) 的 1:1 转动。θ ≈ 64°–280° 时视线背对她（她在房间南缘）。要始终框住她，房间视角就不能 360° 自由看。
- 若只在带内强行看她，在 θ ≈ 60° 时，要以房间方向取景同时让她在画内，镜头需要在她身后约 0.4 m：贴脸近景，而且这里离墙 0.07–0.2 m（roomArm 120–250°）。两条用户约束都被违反。

## 4 运动与过冲

### 4.1 拖动/捏合
位姿 = pose(θ, p, dist)，不经过 solveRoom/roomTrack 的线/角跟随器。所以拖动时的取景 = 几何属性，过冲为 0，帧率无关。

### 4.2 惯性滑行：精确积分
- 现状 `step()`：先 yaw += v·dt，再 v *= e^{−dt/τ}。在 30/60/120 fps 下终点差 **2.09°**（实测）。
- r10：yaw += v·τ·(1 − e^{−dt/τ})，然后 v *= e^{−dt/τ}（τ = velTauS 0.16），pitch、dist 同理。这是闭式解，**步长无关**（实测差 0.000°）。θ(t) 单调趋近终点，过冲 0。

### 4.3 仍保留的滤波（非输入运动）
- 只用于 beginReturn/roomFrom 的回位、seed fade、模式切换。
- 用**精确离散的临界阻尼**：
  - e(t) = (e₀ + (v₀ + ωe₀)t)·e^{−ωt}
  - v(t) = (v₀ − ω(v₀ + ωe₀)t)·e^{−ωt}
- 每帧用这两个闭式解推进 dt，与步长无关。e₀·v₀ ≥ 0 时（包括从静止开始）最多过零 0 次，即不过冲。
- 角加速度上限沿用 angAccDegS2 100 ≤ 110。
- r9 在 30 fps 下过冲 9.7°，我推测来自显式欧拉推进的刚性跟随器（ωdt ≈ 0.8）。r9 代码不在本机，未核实。

## 5 折中（无法完全满足的，直接说明）

### 5.1 惯性滑行的 110 上限
- 滑行中的附加角加速度 = a''ω² + (J−1)·ω̇，其中 ω̇ = −ω/τ，J 为视角每输入度转角，带内 0.65–1.38。两项都随 ω 增长。
- 实测：

  | 松手速度 | 附加角加速度 | 结果 |
  |---|---|---|
  | 30°/s（带外 / 带中 / 核心边缘） | ≤ 78 | ✅ |
  | 90°/s | 228 | ❌ 超过 110 |
  | flick 160°/s | 1063 | 按曲率门槛验收 |

- 做过的尝试：按到带距离制动的滑行限速 |v| ≤ √(ωc² + 2a·d)（ωc 26°/s，a 100°/s²），只降到约 194，而且会改变手感。已放弃。
- **规格决定**：惯性滑行是手势动量，归入“输入运动”，按曲率门槛验收（滑行速度 ≤ 松手速度，所以 ≤ κ·ω_release² + 有界的 (J−1)ω̇ 项）。
- 30°/s 及以下松手的滑行，仍要求满足 110。

### 5.2 镜头线加速度
纯函数镜头的线加速度 = p''·ω²。
- 实测 max|p''| = 0.0145 m/deg²，出现在核心内 θ≈7.5°、dist 3.35，即包络推近处。对应 30°/s 时 13 m/s²，90°/s 时 117 m/s²。
- 即使是 r = 3.35 m 的纯圆环绕，90°/s 时也要 8.3 m/s²。r7–r9 用线跟随器限 2–2.7 m/s²，正因如此才滞后、丢取景。
- r10 优先保证取景与角加速度，线加速度只报告、不设门槛。envK 越小越平缓：k = 2 是椭圆，k = 3 时 max|p''| 为 0.0110，但离她更近。

## 9 实现步骤（FreeOrbit.ts，现有函数名）

1. **`ORBIT_LIMITS.home.roomLook`**
   - 新增 `r10: { edgeA: 330, edgeB: 14, bandDeg: 50, satDeg: 30, envK: 3, gazeM: 1.9 }`。
   - 删除 `yawWarp`。
   - blendFromM/blendFullM、aimFadeW/aimFadeFromW、centreFadeW 在 r10 路径中不再使用。
2. **`roomWeightAt(look, yaw, pitch)`** → 返回 §2.1 的 w(θ)（只与 yaw 有关）。
3. **新增导出函数 `roomEnvelope(yaw, pitch, dist)`**（§2.3）。`roomArm` 保留给其它调用方；r10 环绕不再使用它。
4. **`roomGoalAt(look, yaw, pitch, dist, …)`** → 改成 §2 的纯函数：
   - ψ 饱和 → orbitLens → herAim（frameCentre）→ gaze（roomViewDir）→ 同一个 w 做两次 lerp。
   - 返回 `{ pos, dir, w, arm }`。
   - 删除 yawWarp 那一行（line ~540）。
5. **`solveRoom(...)`**：
   - 室内直接用 roomGoalAt 的结果作为 LookPose。
   - 不再经过 roomTrack 的线/角跟随器（goalSpeedMS、linAccMS2、omega 只留给回位）。

6. **`roomTrack(t)`**：
   - 只在 `mode === 'returning'` 或 seed fade 期间运行。
   - 用 §4.3 的临界阻尼闭式解：每帧推进 dt，不用欧拉；角加速度上限 100。
   - 其它时候直接把姿态设为 roomGoalAt。
