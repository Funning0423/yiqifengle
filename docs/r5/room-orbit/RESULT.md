## 改了什么（`FreeOrbit.ts`）
1. **删除瞄准偏置**：`ROOM_BIAS`、偏置字段、getter、目标计算、施加分支和跟随器全部删除。
2. **视线分两种，按 s 混合（`ROOM_VIEW`）**：
   - 房间区：视线 G = 输入的视线（不变）。
   - 绕她区：视线 L = 从**镜头当前位置**看向她身体中心（她 22 个极值点包围盒中心），再用 `frameCentre` 按极值点微调，让全身居中。输入只控制轨道角度和镜头位置；位置跟随器沿用 r7（刹车曲线 + jerk 30 m/s³ + 墙/她屏障，无前馈）。
   - 混合在角速度域里做（“携带视线”）：每次求解 V += s·ΔG + (1−s)·ΔL；另有一个加速度/加加速度受限的修正速率，把 V 拉向 V* = L + s·wrap(G−L)。所以 s 变化时视线没有跳变，角速度也没有阶跃。
   - s 的跟随：|s′|·|ω_G−ω_L| ≤ 30°/s²，|s″|·|ω_G−ω_L| ≤ 900°/s³；s 软边界 −0.25..1.25，接近目标时吸附。
   - s 的目标：
     - 即将进入绕她区：取预测窗口内 w 的最小值。窗口 = min(1.2 s, 0.8 s + |手速|/90°/s²)，手速由求解间隔估计，0.15 s 滤波。
     - 刚离开绕她区（w_in≤0.1 时开始离开）：min(预测 w 最大值, 9°/gap)。
     - 其他情况：w_in。
3. **镜头位置跟随器变柔**：加速度 2.7 → 2.0 m/s²，刹车 2.7 → 2.0 m/s²，最大速度 2.2 → 1.8 m/s。看向她时，镜头自身的运动会带来视线角加速度；不变柔的话，附加角加速度会到 120–140°/s²。
4. **首次拖动淡出**：剩余倾角改为相对第一帧混合视线计算，淡出加速度 45°/s²。
5. **保留 r7 的**：最小捏合 1.9 m、静止 0 帧出框、yaw 重映射、镜头高度上限 1.55 m。

## 改了什么（全部在 `FreeOrbit.ts`，视线仍是输入的纯函数）
1. **镜头位置跟随器（r7a，23a2ecf0）**：刹车曲线 + 加加速度限制（jerk 30 m/s³，加速度 ≤2.7 m/s²），去掉目标限速 0.8 m/s，墙壁屏障带 0.25 s 前瞻（拐角处不再冲出去）。
2. **最小捏合距离 1.25 → 1.9 m**。1.6 m 不够：斜视角下她的身体宽度在 390×844 竖屏上到 0.97（安全框 0.9）；1.7 m 仍有 ≈580 个静止姿态出框，1.85 m 剩 3 个，1.9 m 为 0。
3. **镜头轴线穿过她的身体中心**（`lensCentreOffset [-0.017, 0, -0.12]`，臂长计算用的盒子在 −z 放宽 0.15 m，让轴心可以落在她身体中心），并按她身体的 22 个极值点**横向平移镜头**让她居中（`frameShift`，只动位置，不转视线）。
4. **视线俯角范围**：`viewDown = softClamp(pitch + 8°, 9°, 31°)`，只依赖输入 pitch（匀速 yaw 拖动时不产生角加速度）。低 pitch 时镜头高度被地板限住，原来会仰视、她掉出画面下沿。
5. **镜头天花板 1.55 m**（`lensMaxY`）：避开挂饰包围盒（env_int_anim_small_props，底 2.19 m）的 0.6 m 净空，否则 clearPose 把臂长拉短到 1.1 m，她装不下。
6. **yaw 300/315：** 只移轴心不够。西墙限制了沿她轴线的镜头距离：yaw 315 时只有 1.58 m，yaw 300 时 1.31 m，而装下她需要约 1.75–1.9 m。所以改为**西墙扇区 yaw 重映射**（`yawWarp`：以 300° 为中心 ±75°，最大 +13°，单调，不锁 yaw），快速经过装不下她的扇区：
   - yaw 315 现在绕她，w 0.003，全身在安全框内；
   - yaw 300 在房间视角（w=1）。
   - 代价：这段映射本身的角加速度随手速平方增长，约 0.0114°/°² × 手速²：30°/s 时 10°/s²，90°/s 时 92°/s²，160°/s 时 **290°/s²**。测试只在 ≤90°/s 时断言，160°/s 只记录。
7. **混合阈值** blendFrom/Full 1.45/0.95 → 2.1/1.6，让“绕她区”（w≤0.1）只覆盖臂长足够装下她的方向：yaw 309–20°。

## 改了什么
1. **只限镜头位置。** 目标限速 0.8 m/s、跟随器加速度上限 2.6 m/s²、墙法向保护，三者都只作用于位置。
   视线方向就是轨道方向本身 `−u(yaw, pitch + 8°)`（`roomViewDir`），只由玩家的 yaw/pitch 决定：不看位置、不看混合权重，也不经过任何跟随器，所以不会落后于输入，混合过程也不会让视角自己转。
2. **过场返回。** 返回期间拖动本来就被忽略。视角走一条定时的 yaw/pitch smootherstep 曲线：
   - 时长 T = √((5.78(|Δyaw|+|Δpitch|) + 3.52|Δyaw·Δpitch|) / 100°/s²)，下限 0.55 s；
   - 结束时正好落在输入视角上，没有吸附。
3. **第一次拖动。** seed 时反解 yaw/pitch，让输入视角等于作者镜头的视角。pitch 上下限够不到的剩余倾角，在第一次拖动后 0.8 s 内用 smootherstep 淡掉（作者镜头这里为 0）。
4. **构图。**
   - 轨道支点向她坐姿身体的平面中心移动：`pivotOffset [−0.2, 0, 0]`。z 不能动，否则支点会出 0.2 m 内缩框，所有 yaw 都会变成中心看出；测试里加了守卫。
