## 3. 路线图和规则

### 3.1 地区顺序（Funning 2026-11-09 16:29 定）
**COAST01–09 → 雪山口 → 秋日铁路 → 黎明云海 → 温泉谷 → 世界著名景点批次**：峡湾极光栈道（r10）→ 沙漠绿洲庭院（r11）→ 白阶海港台地（r12）→ 石灯苔庭（r13）→ 云瀑观景台（r14）→ 峰顶茶室 → ……
- **只追加，不替换、不减少**已规划的地区和关卡。现在的问题是关卡少、场景少。
- **计划不能跑空**：一批做完，马上在同一份计划后面追加下一批世界景点。主题用通用地标氛围，不用商标或版权形象，也不要求写实。
- 详见 `docs/handoff/20261110/plans/QIFENGLE-场景关卡路线图-v2.md`、`COAST01-09-DESIGN-PACKAGE.md`、`COAST02-09-MECHANICS.md`、`SCENE-ROADMAP-20261016.md`、`DESIGN-20261015.md`、`plan-brief-20261105.md`。

### 3.2 每个地区的硬规则
- 分包 ≤ **943,718 B**；场景 ≤ **3000 三角面**。
- 每区 **8 关**，每关 **14–24 步**。
- Node 随机对局胜率在关与关之间 **0.9 ↔ 0.6 起伏**，不能单调。
- **layout-unique** 必须通过（D4 对称 + 平移判重，跨地区比较关卡序列结构）。相邻关的主机制组合要不同。
- **棋盘融合**：棋盘画在该场景自己的地面上（湖面、沙滩、雪坪、木栈、庭院地面等），间隙为 0，不要浮着的木托盘。湖畔的验收参考图是 `docs/handoff/20261110/refs/lakeside-fusion-accept-funning-20261105.png`，仓库里对应 `art/regions/lakeside/renders/lakeside_r5_still_graded.png`。
- 离开棋盘回到进入点，不走气球。调试入口用 `?qfPre=unlock-<region>`，只写隔离的测试存档。
- 场景 GLB 的 Creator meta **必须在 Mac 上由 Creator 3.8.8 首次导入时生成**，不要手写子资源 UUID。每个区的步骤在 `docs/handoff/<region>-wireup.md`。

### 3.3 冻结项和质量线
- **气球几何和外观冻结**。永远不要提交 `transport_balloon.glb.meta`。
- 画面目标是**原神级**。
- 角色建模不能只做到「不穿模、测试通过」。脸和身材要好看，比例自然，衣服有质感，动起来不变形、裙子不掀，在实际游戏镜头下也要站得住。角色打磨还**没有**最终验收。参考图是 `refs/char-target-20261106.png`，反例是 `refs/char-face-fail-20261105.png`。
- 性能：Mac 上约 60fps，但 **iPhone 16 Pro 很多地方只有约 30fps，而且发热**（Funning 11-01）。需要找出原因（GPU、内存等）并优化，尤其是动画卡顿。

### 3.4 发布流程
验收通过 → 把 PR 普通 merge 进集成分支 → Mac 守卫构建 → DevTools cli upload → **在 mp.weixin.qq.com 把这一版设为体验版**（二维码长期有效）→ 在 GitHub 交接文档里记下版本号和 SHA。

### 3.5 Mac 测试规则（Funning 的 MacBook Air）
- DevTools 只开**一个小窗口，放在屏幕左边**。
- **绝不绕过锁屏**。锁屏了就等。
- 测试 bot 用 `/tmp/qf-lock-*` 锁文件互斥，跑完自己清理文件。
- **磁盘很紧**（经常只剩几 GiB），构建测完就删。
- 实拍工具和脚本在 Mac 的 `~/qf-autoplay/scene-*`，脚本副本见 `docs/handoff/20261110/mac-qf-autoplay/`。`scene-20261109T2215-fjord/` 是给峡湾准备好的重拍工具。
