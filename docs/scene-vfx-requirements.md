## 1. 美术方向（来自用户，所有条目都适用）

1. 气质：治愈、轻盈、安静、有生活感。低多边形、柔和的二次元感；颜色浅、柔；**不要卡通过头，也不要写实过头**。
2. 用画面和自然物引导玩家，不用文字（例：花粉飘向下一处、灯塔光扫过的方向、风带指向星门）。
3. 白天、夜里都要协调。夜景是低饱和的蓝色调；任何特效在夜里都不能保持白天的纯白或高饱和色（这正是用户这次说烟“太假”的原因）。
4. 风是主题（“起风了”）：凡是会动的自然物，都优先跟风联动，而且所有东西用**同一个风**，方向和节奏一致。
5. 安静：特效是陪衬，幅度宁小勿大，不抢人物和棋盘；进入棋盘玩法后特效退到外围，不遮棋盘（MIG-003 E）。

## 2. 工程现状（从仓库读出来的事实）

### 2.1 区域与流程
- `RegionLoader.ts` 的 `REGIONS` 只有 `island`、`skycity` 两个 3D 区域。每个区域一个 Asset Bundle，运行时按需加载，场景不直接引用（方案 v2：离开区域释放引用，三区不同时常驻）。
- 流程：屋内坐着 → 起身出门（出门运镜，正对她时起风、围裙掀起）→ 小岛待机（路牌“继续旅程”、行囊/旅程册/设置三个 3D 道具）→ 进关卡（潮汐小径 / 花粉草甸 / 天空回声三个地区的棋盘关）或“天空城 · 看看”参观 → 点灯塔回屋（灯塔点击回屋候选目前 HOLD，未安装）。
- 三地区的棋盘关现在用的是 2D 背景（`OriginalLevelBackground.ts`，只画海洋系列）；**花粉草甸、天空回声的棋盘背景都还没有 3D 场景**。
- MIG-003 F 的编排提案：草甸 3 个可组合环境状态（`meadow.fields` 开阔田圃 / `meadow.bridges` 花道风车桥 / `meadow.bells` 风铃轮庭），天空 4 个（`sky.gate` 星门云岸 / `sky.bridges` 折返云桥 / `sky.court` 星庭机器人 / `sky.finale` 远近星环），潮汐 4 个（含 `tide.return` 雾潮灯塔：同一岸线切换薄雾、灯光与远景）。**特效按“环境状态”做，不按关做**，不做 36 个独立场景。

### 2.2 昼夜
- `DayNightContract.ts`：只有 `day` / `night` 两态，按本地时间 18:00–06:00 为夜，或“晴昼”按钮手动切换。现在是**硬切，没有黄昏过渡**。
- 读取：`globalThis.__worldDayNight.snapshot().mode`（`'day'|'night'`），`isWorldVisible()`、`roomLightWeight()`、`windStrength()` 也挂在这上面（`WorldFlowComponent.ts:358`）。
- 夜间做法：名字带 `_night_v22` 的渲染器只在夜里且外景可见时打开（`nightRenderers`）；unlit 背景用材质实例换颜色（`bindUnlitBackdrop`）：天空 `[.18,.24,.46]`、云层 `[.22,.28,.43]`、海面泡沫 `[.35,.48,.64]`。主光夜里 ×0.35、颜色 `(180,198,232)`。
- 要求：特效内部一律用 `nightBlend` 0..1 插值（现在只会收到 0 或 1），将来加黄昏过渡时不用返工。夜间颜色从上面这几组现有色值里取，保证和场景同一个调子。
- **天空之城没有任何昼夜代码**：`SkycityVisitAdapter` 只负责加载和机位，`env_skycity.glb` 里没有天空球、没有夜间网格。

### 2.3 风
- API：`WorldFlowComponent.getWindStrength()`（0..1，每帧轮询）和 `onWindStrength(cb)`。
- 在 `e439b62` 上它还是**过渡版，恒为 0**。真正的风在运镜bot `138bca5`（`work/运镜bot-wind`，还没合进 `int/v1`）：只在出门那段正对她时起风，正对前约 0.2 秒越过 0.95，正对时为 1；`apron_lift` 用 0.95 作阈值。**小岛待机时风力正好是 0**。
- 所以光靠 `getWindStrength()`，岛上的草、烟、云在待机时都不会动。需要一个共用的风模块（见 3.2）：`风 = max(底风(t), getWindStrength())`。底风是常年的轻风，阵风来自出门那一下，以后也可以来自角色动画bot 岛上待机的 `'soft'` 小风。
- 音频已经跟着同一个风：`WindAudio`（风声循环、`notifyApronLift('full'|'soft')`）、`AmbienceAudio.setWindExit()`（出门的海浪、海鸥）。视觉只要读同一个值，声画就自然同步。

### 2.7 包体与引擎限制
- 用户口径：现在总包体约 23.3 MB（上限 30 MiB = 31,457,280 B）；T8 第 1 步之后估算约 22.94 MB。**主包必须 ≤ 4 MB**。
- 角色正式版要留约 600 KB；还有 BGM v1（约 +0.28 MB）、草原整个区域包要进来，所以**特效只能分到很小一块**。
- **引擎的粒子模块（3D/2D）已经关掉**（`settings/v2/packages/engine.json`）。重新打开会让主包里的 cc.js 变大，**不允许**。所有“粒子”效果都用程序生成的小网格、顶点动画或 shader 做，不用 `ParticleSystem`。
- 不加大贴图：能程序生成的就生成（茶汽、路牌涟漪都是 0 字节），必须带贴图的 ≤ 64×64 或 128×128，压缩后单张 ≤ 8 KB。尽量共用 `M_env_palette`（天空之城用 `M_sky_palette`）。
- 场景 glb 现在都是 Tangents=Exclude，特效不要依赖切线或法线贴图。
- 代码要能过 Cocos 的 loose ES5 编译：不要对 Map/Set 用 spread 或 for-of（用 `Array.from(...).forEach`）。
- 首个切片的预算目标（方案 v2）：可见三角 ≤ 120k、Draw Call ≤ 80；iPhone 16 Pro 60 FPS（P95 ≤ 20 ms），中端 Android 30 FPS。

## 3. 通用技术规范（每一条特效都遵守）

### 3.1 结构
- 代码放 `creator-build-project/assets/scripts/vfx/`，每个区域一个宿主：`IslandVfx`、`MeadowVfx`、`SkycityVfx`。各自只管自己创建的节点，挂在一个根节点下（`IslandVfxRoot` 等）；**不改导入模型的材质共享实例**，要改就用 `getMaterialInstance` 并在 dispose 时还原（同 `bindUnlitBackdrop` 的做法）。
- 新建节点一律以 `vfx_` 开头（如 `vfx_smoke_puff_0`、`vfx_beam_cone`、`vfx_beam_halo`、`vfx_wind_ribbon_0`）。这样运镜bot 的镜头遮挡测试和灯塔点击判定可以按前缀统一纳入或排除。
- 生命周期：跟随区域加载/卸载；`Game.EVENT_HIDE` 和宿主暂停时冻结相位，恢复时不追帧、不跳；20 次进出后不泄漏材质、网格和贴图（照 `RoomLightingRig` 的 dispose 测试来）。
- 更新频率：默认 30 Hz（同 `ROOM_LIGHTING.updateHz`）；每帧不分配对象、不做场景查找。
- 减少动态效果：读 `forest-v33-reduced-motion`（`OriginalLevelBackground.currentReducedMotion()` 已有同样的判断），开着时幅度减半、频率减半，闪光关掉。
- 画质分档：每项都要有一个“低档”（中端 Android 用），至少能把数量减半或直接关掉。
- 可选失败：特效加载或创建失败只打 `console.warn`，**画面退回现状**，不阻塞流程（同 `IslandProps` / `createSteam`）。

### 3.2 共用模块
- `vfx/SceneWind.ts`：`wind(t) = max(底风(t), getWindStrength())`。底风 0.15–0.3，周期 6–12 秒，用两个不成整数比的正弦叠加，带一点随机相位；还提供风向（小岛默认从海上吹向陆地，具体方向和运镜bot 对）和阵风包络。所有特效、以后的草和布料都读它。**它只读不写**，不改 `getWindStrength()` 的含义，也不影响 Voice bot 的风声。
- `vfx/SceneNight.ts`：读 `__worldDayNight.snapshot().mode`，输出 `nightBlend`；提供共用夜色表（取自 2.2 那几组现有色值）。
- `vfx/fx_env_soft.effect`（可选，只做一份全项目共用）：柔边 alpha / 加法两个 pass，uniform：`time`、`wind`、`nightBlend`、`dayTint`、`nightTint`、`fadeNear/fadeFar`。做之前先确认 `builtin-unlit` + 顶点色/顶点 alpha 不够用；够用就不新增 effect（每多一个 effect，区域包里的打包 json 都会变大）。
- 不用深度贴图做软粒子（微信 WebGL1 路径不保证有），柔边靠顶点 alpha、菲涅尔和距离淡出。

### 3.3 和其他 bot 的接口
- **运镜bot**：镜头遮挡帧测试要把所有 `vfx_` 节点算进去，镜头不能穿进光锥、烟团或云海体积；“朝镜头闪一下”之类的效果要读**当前实际镜头位置**（出门这段镜头会绕她一圈）。运镜bot 正在处理屋内画面（门半掩、压暗）和镜头被棕榈挡住的问题，屋内特效要先跟他对。
- **Voice bot**：需要声音配合的时刻由特效发事件（如 `onVfxCue('windmill_gust')`），不挂在动画事件上（现在手动采样，Cocos 动画事件不一定触发）。风相关的声音已经读 `getWindStrength()`，视觉只要读同一个值就会同步，不需要额外事件。
- **GGbot**：挂载入口。T0 会拒绝改 `WorldIntegrationBoot.ts`，所以**不要改 Boot**。区域宿主的挂载点由 GGbot 提供（或者挂在运镜bot 的 `WorldFlowComponent` 已有的 `mount` 流程里，由运镜bot 改）。动到 T0 白名单里的任何文件，交付时把 sha256 报给 GGbot。路牌夜灯（T9）归 GGbot，特效这边只需要保证色温一致。
- **角色动画bot**：围裙和头发的风效读同一个 `SceneWind`；岛上待机的 `'soft'` 小风如果由他的待机逻辑决定，`SceneWind` 要能接收这个阵风，好让草和烟同时动。

## 4. 小岛（灯塔 / 海岸，含屋内）— 已有资源

### ISL-P0-1 烟囱的烟（用户已提）
- **是什么 / 为什么**：烟囱冒出慢慢上升、膨胀、变淡、被风带走的烟。告诉玩家“屋里有人住、很温暖”。现在的问题：不动、夜里纯白、像几颗串起来的球。
- **表现**：4–6 个烟团交替循环，从烟囱口冒出，上升 1.5–2.5 m，逐渐放大到 2–3 倍，alpha 从 0.5 淡到 0；每个烟团单独转一点、形状略微起伏，**不能看出是一个转着的实心球**。
- **白天**：暖灰（偏米白，比云暗一档），不要纯白。**夜里**：暗蓝灰，取云层夜色 `[.22,.28,.43]` 附近；烟囱口 0.3 m 内带一点微弱的暖色底光（屋里炉火映上来），越往上越冷。
- **风**：读 `SceneWind`。底风时轻微斜向一侧；出门阵风时明显偏向下风，上升高度变低、消散更快；风停后 2–3 秒内慢慢恢复竖直，不能一下弹回去。
- **触发**：外景可见时常驻（`isWorldVisible()` 且外景层打开）；在屋里、关卡里和天空城里关掉。
- **技术**：优先复用 5 个原节点和网格，在代码里覆盖它们的 TRS 和材质实例（先查清 `idle_loop` 的烟球通道为什么没驱动起来，避免两边同时写）；或者换成 1 个程序生成的柔边 billboard 网格（同茶汽 32×64 程序贴图）。
- **性能**：≤ 5 个 draw call（能合成 1 个更好），≤ 200 三角。**包体** ≤ 6 KB（只有脚本）。
- **依赖**：运镜bot：出门和回屋镜头从烟附近经过，镜头不能穿进烟团；GGbot：挂载点。
- **验收**：白天/夜晚 mp4 里看得出上升、膨胀、消散、风偏；夜里不发白；切昼夜 100 次相位不跳；出门阵风那一下烟明显偏，风停后柔和回正。

### ISL-P0-2 灯塔光束（用户已提）
- **是什么 / 为什么**：夜里灯塔扫出柔和的光，是小岛夜景的主角，也是“灯塔在那里”的视觉引导（以后点灯塔回屋时也靠它吸引注意）。现在的问题：12 秒匀速一圈（约 30°/s），硬边，像直升机螺旋桨。
- **表现**：
  - 锥形光束，从灯室向外**越远越宽、越远越淡**，边缘柔（横截面 alpha 从中心往外衰减，不能有硬边），加法混合的伪体积光，带一点雾感（沿光束方向有很淡的明暗起伏，可以慢慢流动）。
  - 转速放慢：约 20–30 秒一圈（具体数值看预览再定），匀速或带极轻的速度起伏，不要机械。
  - 光束扫到**当前镜头位置**方向时，灯室亮一下，带一个小光晕（`vfx_beam_halo`，闪光持续约 0.3–0.5 秒，柔入柔出）。
  - 扫过海面时，海面上留下一道淡淡的反光，跟着光束移动、慢慢淡掉。
- **白天**：不可见或几乎不可见（灯室光晕可以保留现有的 `env_lighthouse_lamp_glow_v22`，但亮度压低）。**夜里**：暖黄 (1,.9,.62) 一类的颜色，整体亮度克制，不能把夜景照成白天。
- **风**：不直接联动；可选：雾感流动的速度跟风稍微相关。
- **触发**：夜里，且外景可见时。
- **技术**：在 `env_lighthouse_beam_night_v22` 的基础上改（或者换成 `vfx_beam_cone`：一个 12–16 段的开口锥，顶点 alpha 做径向和纵向衰减）；转速由代码驱动，代替 `idle_loop` 里 pivot 的匀速旋转（要确认覆盖后不会和动画抢写）。海面反光用海面上方贴一片很淡的加法条带，或者用海面材质的 uniform，先选成本低的那个。
- **性能**：≤ 3 个 draw call（光锥 + 光晕 + 海面反光），≤ 400 三角；加法透明，注意竖屏下全屏的过度绘制。**包体** ≤ 10 KB（脚本，加上可能需要的共用 effect）。
- **依赖**：
  - 运镜bot：**镜头任何时候都不能飞进光锥里**（否则整屏发亮），光锥节点要加进他的镜头遮挡帧测试；闪光按当前镜头位置算。
  - 灯塔点击回屋（HOLD）：光锥、光晕不接收点击，`hitLighthouse` 不能因为光束而命中。
  - GGbot：路牌夜灯的色温和光束保持同一暖色系。
- **验收**：夜里 mp4：光束柔边、远端淡出、转得慢；扫过镜头方向时灯室有一下闪光；海面有一道淡淡的反光跟着走；白天 mp4 看不见光束。遮挡测试里，出门和回屋每一帧镜头都不在光锥内。

### ISL-REF 路牌夜灯（只做参考，GGbot 负责）
路牌灯的光照到木板、柱子和水面倒影（T9），以及三个按钮标签夜里压暗，都由 GGbot 做。特效这边只要求：灯塔光束、窗灯和路牌灯用同一组暖色。

### ISL-P1-1 海面闪光和岸线泡沫呼吸
- **为什么**：用户要海水更真实。白天阳光下海面有细碎闪光，岸边泡沫一涨一退，画面就“活”了。
- **白天**：靠近太阳方向的海面有稀疏的细碎高光，慢慢闪烁。**夜里**：闪光换成月光方向，更少、更冷；泡沫用现有的夜色 `[.35,.48,.64]`。
- **风**：风大时闪光密一点、泡沫推得远一点。
- **技术**：在海面材质上加 uniform（时间 + 噪声），或者叠一层很薄的加法闪光条带。**必须先和现有的海水候选（S/T/U，其中 U 结构水还没在微信里跑过）对齐**，不另起一套海面，不覆盖别人的海面文件；所以这一项排在 U 的结论出来以后。
- **性能**：+0–1 个 draw call。**包体** ≤ 6 KB。
- **验收**：白天/夜晚 mp4，闪光不刺眼、不像雪花；泡沫进退周期 6–10 秒。

### ISL-P1-2 云：慢慢飘、边缘柔
- **为什么**：用户说现在的云“像冰川”。云要软、要慢慢动。
- **表现**：`env_cloud_layer` 整体非常缓慢地飘（UV 滚动或节点平移），边缘和底部更柔、更透；夜里沿用云层夜色并再暗一档。
- **风**：飘动速度跟风（底风很慢；出门阵风时稍快）。
- **技术**：材质实例的 uniform，或者在代码里慢慢平移；不改网格。和运镜bot 确认构图（出门升降镜头会拍到云）。
- **性能**：0 个新 draw call。**包体** ≤ 4 KB。
- **验收**：60 秒 mp4 看得出在动，但不分散注意力；边缘不再是硬的冰块感。

### ISL-P1-3 海鸥航线
- **为什么**：用户明确要求海鸥“不能一直转同一圈”。
- **表现**：两只飞鸥沿几条不同的路线飞，每次路线、高度、速度略有不同；偶尔滑翔不扇翅；出门那段的远、近海鸥和 Voice bot 的海鸥声时间对上。夜里不出现，或者只远远地飞一次。
- **风**：顶风时飞得慢、身体稍倾。
- **技术**：在代码里覆盖 `env_anim_seagull_fly_0x_v22(_orbit)` 的 TRS，用几条样条随机挑；参考旧候选 island-life v3v 的做法（那个候选没在微信里跑过，**只参考，不整包安装**，交接要求按 SHA 逐项拿）。
- **性能**：0 个新 draw call。**包体** ≤ 6 KB。
- **依赖**：Voice bot（出门海鸥的时间点）；运镜bot（海鸥不能扫过镜头近处）。
- **验收**：3 分钟录像里看不出重复的圈。

### ISL-P1-4 出门那一阵风的风带
- **为什么**：出门正对她的那一刻是全游戏“起风了”的点题镜头。几条很淡的风的丝带从画面一侧掠过，围裙掀起，和风声同时到达。
- **表现**：2–4 条细长、半透明、柔边的丝带，沿风向掠过人物身后和前景，持续 1–1.5 秒，和 `apron_lift`（阈值 0.95）的翻起同时到峰值。颜色白天偏白、略带天色，夜里是淡蓝灰，**很淡**，不像卡通速度线。
- **风**：直接由 `getWindStrength()` 驱动（越过 0.95 时最强，落下时消散）。
- **触发**：只在出门这段的那一次阵风里出现；岛上待机的 `'soft'` 小风里不出现或者极弱。
- **技术**：程序生成的条带网格，顶点 alpha + UV 滚动。
- **性能**：≤ 2 个 draw call，只在约 1.5 秒内存在。**包体** ≤ 8 KB。
- **依赖**：运镜bot（构图、不挡她的脸、帽子安全边距）；角色动画bot（`apron_lift` 翻起帧）；Voice bot（`notifyApronLift('full')` 已经由 GGbot 的驱动发出，视觉读同一个风值就能同步）。
- **验收**：mp4 里风带、围裙、风声三者峰值相差 ≤ 0.1 秒；静帧里不显眼。

### ISL-P1-5 夜里亮着的窗：暖光轻轻呼吸
- **为什么**：夜里远远看见窗里有暖光，就是“家”。
- **表现**：灯塔塔身的窗、门口的暖光非常轻地起伏（像烛光，幅度 ≤ 10%，周期 3–6 秒，不规则），不闪烁。
- **技术**：塔窗材质实例的 emissive / 颜色 uniform。门口暖光运镜bot 正在调亮，以他的版本为准，只加呼吸。
- **性能**：0 个新 draw call。**包体** ≤ 2 KB。
- **依赖**：运镜bot（门口暖光、屋内压暗）。

### ISL-P2-1 夜空的星星
- 夜里天空上方稀疏、缓慢闪烁的小星星，避开月亮和光束扫过的区域。程序生成的点阵网格（1 个 draw call），白天关闭。**包体** ≤ 4 KB。
- 不做萤火虫：小岛是海岸，萤火虫放到草原（MDW-P1-3）更合适。

### ISL-P2-2 屋内：光柱里的浮尘、灯焰
- 用现有锚点 `fx_sun_shaft_tower_r`、`fx_dust_motes`、`fx_flame_*`：白天窗边光柱里几粒慢慢飘的浮尘；夜里灯焰非常轻地跳动。
- **前提**：用户刚说屋里“看着有点乱”，运镜bot 正在从画面上处理（门半掩、压暗）。这一项**等运镜bot 的方案定了再做**，而且只能让画面更安静，不能更花。**包体** ≤ 4 KB，≤ 2 个 draw call。

### ISL-P2-3 沙滩小草和小花随风摆
- **只有模型里真的有草和花才做**。现在的 glb 里只有棕榈、风铃、窗帘会动（`idle_loop`，跟风无关）。可选：棕榈和风铃的摆幅接 `SceneWind`（出门阵风时摆得大一些），需要先确认能不能在 `idle_loop` 上叠加权重而不改动画资源。**包体** ≤ 3 KB。

**小岛合计**：P0 ≤ 16 KB；P0 + P1 ≤ 42 KB；全部 ≤ 53 KB（上限 60 KB）。新增 Draw Call：全部做完最多 +14（P0 ≤ 8；出门风带只在约 1.5 秒内存在，屋内两项和外景不同时出现）。

## 5. 风车草原（花粉草甸）— 场景还没做

> 现状：没有 `region_meadow` bundle，没有风车、草地、河流、风铃的模型；棋盘关现在用的是 2D 背景。场景建模不归场景特效bot（谁来建模待定，见第 9 节问题 1）。
> 所以草原分两步：**第一步**在独立测试场景里（灰模平面 + 几个替身网格）把 shader 和脚本原型做出来，出离线预览；**第二步**等草原场景到了再接，按真实网格调参数。

草原的核心是“风”：草浪、风车、花粉、风铃、云影全部读同一个 `SceneWind`，方向一致。地区名就叫“花粉草甸”，章节简介是“循着花粉与风，走进草甸”，所以**花粉是这个区的视觉引导**。

### MDW-P0-1 风吹草浪
- **为什么**：交接里明确要“风吹草浪”，是草原的第一印象。
- **表现**：草叶整体按风摆，并有一道道浪从上风处滚向下风处（世界空间的低频波 + 高频轻颤），浪经过的地方草色稍微变亮（草叶背面翻过来的感觉）。
- **白天**：浅绿到黄绿，浪峰偏亮。**夜里**：低饱和蓝绿，浪峰的提亮压得很低。
- **风**：风越大，浪越快、幅度越大、间距越短；底风时只有很慢的起伏。
- **技术**：草的顶点 shader（按高度加权的位移，读 `wind`、`time`、风向）；草用实例化或合批的卡片网格，共用调色板材质。要有低档：不支持实例化或超预算时，换成烘焙的草色地面（`BakedGroundTexture` 已经预留了这条路，贴图 1024 约 0.6 MiB，**这张贴图算场景包体，不算特效**）。
- **性能**：草的 draw call ≤ 3（按区块合批），草三角预算和建模方一起定（建议 ≤ 25k）。**包体** ≤ 10 KB（effect + 脚本）。
- **依赖**：建模方（草卡片的 UV 和顶点色约定：顶点色 R = 摆动权重）；运镜bot（入口镜头）；GGbot（棋盘玩法时草浪退到外围、降低幅度，不干扰棋盘）。
- **验收**：灰模预览：风起风落 20 秒 mp4（白天/夜晚）；接上真实场景后在 Mac 上看帧时间。

### MDW-P0-2 风车随风转
- **为什么**：风车是“风车草甸”的地标，也是最直观的风力表。
- **表现**：叶片转速 = 底速 + k × 风；起风时慢慢加速，风停时靠惯性慢慢减速（不能瞬间变速）；远景风车慢一些、相位错开。
- **白天/夜里**：转法一样；夜里风车窗如果有灯，和小岛窗灯用同一暖色并轻轻呼吸。
- **技术**：代码转叶片节点（一阶平滑的角速度）。0 个新 draw call。**包体** ≤ 3 KB。
- **依赖**：建模方（叶片做成独立节点，统一命名如 `env_meadow_windmill_XX_blades`，轴向写进 manifest）；Voice bot（风车吱呀声按转速推，特效提供 `bladeSpeed()` 给他读）。
- **验收**：mp4 里加减速平滑；`bladeSpeed()` 曲线和风力曲线对得上。

### MDW-P0-3 云影
- **为什么**：交接要求有云影，大片云影慢慢扫过绿坡，画面有呼吸、有空间感。
- **表现**：柔和、低对比的大块阴影，沿风向缓慢移动。夜里关闭（或者换成极淡的月光云影，默认关）。
- **技术**：**按交接要求，用 UV/材质方案**：在地面和草的材质里按世界坐标采样一张很小的噪声图（≤ 128×128，压缩后 ≤ 8 KB）或者纯程序噪声；**不用一张巨大的透明覆盖层**。先确认渲染路径和透明排序。
- **性能**：0 个新 draw call。**包体** ≤ 10 KB。
- **依赖**：建模方（地面材质要能加这个 uniform）；GGbot（棋盘区域内云影减弱，不影响棋子辨认）。
- **验收**：60 秒 mp4；棋盘玩法截图里云影不影响辨认棋子。

### MDW-P1-1 花粉和蒲公英：视觉引导
- **为什么**：“循着花粉与风”。几粒发光的花粉顺着风飘向下一处（入口 → 河边 → 风铃 → 棋盘），玩家自然会跟着看过去，不用文字。
- **表现**：稀疏（同屏 ≤ 30 粒），柔和的暖白小光点，顺风飘、带一点上下起伏；偶尔有蒲公英种子飘过。夜里光点稍亮、偏暖，像小灯。
- **风**：完全跟 `SceneWind` 走。
- **触发**：入口和互动镜头时引导方向；进入棋盘后飘到外围或减少。
- **技术**：一个程序生成的点阵网格，在顶点 shader 里按时间和风位移（不用 `ParticleSystem`）。1 个 draw call。**包体** ≤ 8 KB。
- **依赖**：GGbot / 关卡流程（下一处目标点的位置）；Voice bot（花粉到达目标时可选一声很轻的铃音，特效发 `onVfxCue('pollen_arrive')`）；运镜bot（入口镜头里看得到）。
- **验收**：不认识这个游戏的人看 mp4，能说出“花粉往那边飘”。

### MDW-P1-2 河流和风铃
- **为什么**：交接要求河流和铃铛在入口和互动镜头里看得见（`meadow.bells` 风铃轮庭）。
- **表现**：河面 UV 缓慢流动，带少量细碎闪光（复用小岛海面闪光的做法）；风铃随风摆，风大时摆得大。夜里河面变暗，闪光换成月光。
- **技术**：河面材质 uniform（UV 滚动 + 闪光）；风铃节点由代码按 `SceneWind` 摆。0–1 个新 draw call。**包体** ≤ 8 KB。
- **依赖**：建模方（河面单独的网格和 UV 方向；风铃节点命名）；Voice bot（风铃声按摆幅推）。

### MDW-P1-3 夜里的萤火虫
- 夜里草丛上方稀疏的萤火虫（同屏 ≤ 20），慢慢明灭、慢慢游走，颜色是柔和的黄绿。白天关闭。1 个 draw call。**包体** ≤ 4 KB。

### MDW-P2-1 蝴蝶
- 白天花丛附近 2–3 只低多边形蝴蝶（共用调色板，翅膀两片网格），风大时躲开或停在花上。**包体** ≤ 6 KB，≤ 1 个 draw call。

### MDW-P2-2 夜空的星星
- 和小岛 ISL-P2-1 共用实现。注意：草原的夜空本来计划用一张约 2.0 MiB 的夜景图（`SkyNightTexture.ts`），如果那张图里已经画了星星，这一项就不做；做的话只做闪烁层。**包体** ≤ 2 KB。

**草原合计**：P0 ≤ 23 KB；全部 ≤ 51 KB（上限 80 KB，留出跟真实场景磨合的余量）。新增 Draw Call ≤ 8（不含草本身）。

## 6. 天空之城 — 3D 场景已有，没有昼夜、没有特效

> 交接：天空是**美术验收最高优先级**，要保留云海、巨型机器人、层次空间和探索感。机器人 9 m 的外观未经用户批准，特效不碰机器人。
> 现在 `env_skycity.glb` 只在“天空城 · 看看”参观模式里用；天空回声的棋盘关还没有 3D 背景。

### SKY-P0-1 云海流动
- **为什么**：云海是天空之城的底，现在只是整体旋转（`sky_ambient_loop` 里 `env_sky_cloudsea` 只有 rotation）。要有“在流动、软软的”感觉，**不能像冰川**（小岛云层的同一个问题）。
- **表现**：云海表面缓慢起伏（低频顶点位移），表面明暗缓慢流动，边缘柔、远处融进天色；靠近浮岛的地方有一点点翻涌。
- **白天**：奶白偏暖，阴影偏淡紫蓝。**夜里**：蓝灰，取小岛云层夜色一类；月光一侧稍亮。
- **风**：流动速度跟 `SceneWind`。
- **技术**：`M_sky_cloud` 的材质实例 + 顶点 shader（共用 effect）；不改网格。
- **性能**：0 个新 draw call。**包体** ≤ 10 KB。
- **依赖**：运镜bot（参观机位从云海上方看，镜头不能进入云海体积）。
- **验收**：白天/夜晚 30 秒 mp4。

### SKY-P0-2 远景薄雾和层次
- **为什么**：“层次空间”。远处的浮岛、积云被一层薄雾隔开，空间才深。
- **表现**：远景（`env_sky_islets_far`、`env_sky_cumulus_far`、远处的浮石）按距离慢慢融进天色；中景偶尔有一缕薄雾缓慢飘过（1–2 片程序生成的柔边卡片）。夜里雾变成深蓝，压暗远景。
- **技术**：远景材质实例的颜色/alpha 随距离混合（不用全局雾，先确认 Cocos 微信路径上的雾开销）；雾卡片用加法或 alpha 柔边。
- **性能**：≤ 2 个新 draw call。**包体** ≤ 6 KB。
- **依赖**：运镜bot（镜头不能穿雾卡片）。

### SKY-P0-3 天空之城的夜景
- **为什么**：现在整个天空城只有白天，用户要求所有场景白天和夜里都协调。
- **表现**：夜里主光变冷变暗（沿用小岛的 ×0.35 和 (180,198,232)），调色板材质整体压成低饱和蓝调；`M_sky_palette_emissive`（风之核、遗迹发光部分）在夜里成为主要光源，轻轻呼吸；天空背景换夜色。
- **技术**：材质实例换色 + 主光参数，读 `SceneNight`。天空城没有天空球，背景色可能要 GGbot 或运镜bot 那边提供相机清屏色，或者另外加一个很便宜的渐变天空（0 贴图）。
- **性能**：+0–1 个 draw call。**包体** ≤ 4 KB。
- **依赖**：GGbot（`SkycityVisitAdapter` 里没有昼夜接入，挂载点和昼夜切换要他提供）；运镜bot（参观机位下的夜景构图）。
- **验收**：白天/夜晚同机位对比图 + mp4。

### SKY-P1-1 大树冠下的光柱（白天）
- 阳光从 `env_sky_greattree_canopy` 的缝隙斜射下来，几道柔和、缓慢明暗变化的光柱，里面有几粒浮尘。夜里关掉，或者换成很淡的月光柱。3–4 张加法柔边卡片，≤ 2 个 draw call。**包体** ≤ 6 KB。

### SKY-P1-2 风之核、风带和风筝丝带：引导方向
- **为什么**：天空城“风”的源头。几条很淡的风带绕着浮岛缓慢流动，指向星门 / 机器人 / 星庭，引导玩家往那里看。
- **表现**：`env_sky_island_windcore` 轻轻脉动（发光呼吸）；2–3 条细长丝带沿弧线绕岛流动（UV 滚动 + 顶点 alpha）；`env_sky_pennant_01/02` 和 `env_sky_windchime_01` 的摆幅接 `SceneWind`。白天丝带接近白色、很淡，夜里淡蓝且略亮（像月光里的风）。
- **触发**：常驻；状态变化（如 `state_gate_before` → `after`）时风带短暂变亮一次，指向刚解锁的地方。
- **技术**：程序生成的条带网格，≤ 2 个 draw call。**包体** ≤ 8 KB。
- **依赖**：GGbot / 关卡流程（状态切换事件和目标位置）；Voice bot（风铃声）；运镜bot（风带不挡机器人和棋盘）。

### SKY-P1-3 瀑布雾
- 在现有 `env_sky_waterfall_mist` 的基础上，让雾气从瀑布底部缓慢翻涌、往下风飘散，夜里变成蓝灰。0–1 个新 draw call。**包体** ≤ 4 KB。

### SKY-P1-4 星环的闪光
- `sky.finale` 远近星环：`env_sky_starring` 上的星点慢慢闪烁；`state_ring_after_stars` 点亮时，星光沿环流过一圈（一次）。0–1 个新 draw call。**包体** ≤ 4 KB。
- 依赖：GGbot（状态事件）；Voice bot（星的音效时间点，特效发 `onVfxCue('starring_lit')`）。

### SKY-P2-1 夜空：星星和极光
- 夜里天空上方满天星（比小岛更密，因为更高）；极光只做一条很淡、很慢的绿蓝色带，放在远处地平线上方，不抢云海。默认先只做星星，极光看预览再定（风格上可能偏写实，需要用户点头）。**包体** ≤ 10 KB，≤ 2 个 draw call。

### SKY-P2-2 机器人互动的小反馈
- 机器人浇水、送花（`robot_watering` / `robot_give_flower`）时，花朵周围冒出几粒小光点，持续 1 秒。只在 `SkycityRobotInteract` 提供事件后再做，不碰机器人本身。**包体** ≤ 3 KB。

**天空之城合计**：P0 ≤ 20 KB；全部 ≤ 55 KB（上限 80 KB）。新增 Draw Call ≤ 11。

## 9. 待项目经理（Grok Bot）确认的问题

1. **草原场景谁来建？** 现在团队里没有场景建模的 bot（角色动画bot 只做人物动作，场景特效bot 不建模）。草原的地形、草、风车、河流、风铃需要一个负责人和时间表；在那之前草原特效只能做离线原型。
2. **天空回声的棋盘关要不要 3D 背景？** 现在只有“天空城 · 看看”参观模式用 `env_skycity.glb`；棋盘关还是 2D 背景。特效先只做参观模式，还是要等棋盘背景定下来？
3. **小岛待机时要不要底风？** `getWindStrength()` 在岛上待机时规定为 0（运镜bot 的约定）。本文提议特效用 `max(底风, getWindStrength())`，底风只给视觉用。要确认：Voice bot 的风声和角色动画bot 的围裙/头发要不要也读这个底风，还是只有场景特效读。
4. **昼夜要不要过渡？** 现在是 18:00 硬切、按钮硬切。特效会按 0..1 做好插值，但要不要加黄昏（比如 17:30–18:30 渐变）是产品决定，而且要改 `DayNightContract`（运镜bot / GGbot 的文件）。
5. **海面（ISL-P1-1）等不等 U 结构水？** 交接说 U 候选没在微信里跑过、新的 e337 事务包经 QA 后才有条件放行。是先让 U 进入 Mac 测试，还是特效只在现有海面上加闪光？
6. **旧候选 island-life v3v（海鸥 + 烟，未在微信里跑过）要不要拿来用？** 建议只参考其中的做法，不整包安装（交接要求按 SHA 逐项应用）。请确认。
7. **烟和光束要不要接管 `idle_loop` 的轨道？** 烟球和灯塔 pivot 的动画都写在 12 秒的 `idle_loop` 里。由代码接管意味着要处理“动画和代码同时写”的问题；另一种是重新导出 glb 把这几条轨道去掉（会改 glb 和 hash，牵动 T1 依赖和测试）。倾向代码接管，请确认。
8. **天空之城的夜景挂在哪里？** `SkycityVisitAdapter` 没有昼夜接入。挂载点由 GGbot 还是运镜bot 提供？背景色（天空城没有天空球）谁来定？
9. **极光（SKY-P2-1）是否符合“不写实过头”？** 建议先只做星星，极光等用户看了预览再决定。
10. **`tide.return` 雾潮灯塔**（潮汐地区关卡的薄雾、灯光变体）算不算本次范围？它属于潮汐棋盘关的背景，现在也是 2D。建议先不排，等棋盘背景方向定了再说。
